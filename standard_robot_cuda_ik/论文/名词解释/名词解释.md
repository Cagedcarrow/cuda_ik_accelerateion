# 技术名词解释

本文档针对论文《结构感知单核融合的机械臂批量逆运动学CUDA加速方法》中出现的领域术语，按三个类别逐一解释。每条解释面向具有本科工科背景、但不熟悉该具体领域的读者。

---

## 一、CUDA/GPU 计算领域

### 1. CUDA
- **英文**：Compute Unified Device Architecture
- **解释**：NVIDIA 推出的并行计算平台与编程模型，允许开发者用 C/C++ 扩展语言直接控制 GPU 进行大规模并行计算。与 CPU 的"少量强核"不同，GPU 提供"大量弱核"，适合将同一运算施加于海量数据。
- **本文用法**：全部核函数用 CUDA C++ 编写，编译链为 nvcc（CUDA 专用编译器），运行在 NVIDIA RTX 4060 Laptop GPU 上。CUDA 是实现"单核融合"目标的硬件与软件基础。

### 2. 核函数（Kernel）
- **英文**：Kernel Function
- **解释**：CUDA 编程中，在 GPU 上并行执行的函数称为核函数，由 `__global__` 关键字声明。一次核函数启动（kernel launch）会在 GPU 上同时启动成千上万个线程，每个线程执行相同的代码但处理不同的数据。启动本身存在约 5--10 微秒的固定 CPU→GPU 通信开销。
- **本文用法**：将所有 $N\times K$ 个 IK 求解任务和候选筛选全部封装进单个核函数 `IK_LM_Multiseed_Block_Target`，核函数启动次数恒为 1，使调度开销从毫秒级压缩至微秒级。

### 3. 核函数融合（Kernel Fusion）
- **英文**：Kernel Fusion
- **解释**：将原本需要多次核函数启动才能完成的多阶段计算合并为单次核函数启动。融合的好处是消除核函数之间的启动延迟和全局内存往返——中间结果不再写回显存再读出，而是直接在片上（寄存器、共享内存）传递。
- **本文用法**：核心贡献之一。传统方案需要逐种子逐权重分别启动核函数（累计 $N\times K\times W+N$ 次），本文将 FK、雅可比组装、LM 迭代、候选筛选全部融合为一次核函数启动，调度开销占比降至 GPU 总时间的 0.01\% 以下。

### 4. 经线（Warp）
- **英文**：Warp
- **解释**：GPU 硬件调度的最小执行单元，每 32 条线程编为一组经线，以单指令多线程（SIMT）方式执行同一条指令。若经线内线程因条件分支走向不同路径，硬件必须串行执行两条路径——称为经线发散（warp divergence），性能损失严重。
- **本文用法**：每线程块 32 线程恰好构成一个经线，其中 16 条 lane 各承载一个 Sobol 种子计算，线程间执行代码路径完全相同（无分支 LM 算法设计保证），彻底消除了经线发散。

### 5. 线程块（Block）
- **英文**：Thread Block
- **解释**：一组线程的集合（最多 1024 线程），被调度到同一个 SM 上执行，块内线程可通过共享内存和 `__syncthreads()` 进行协作。块之间独立执行，无法直接通信。
- **本文用法**：采用 `<<<N, 32>>>` 启动配置——每个目标位姿分配一个线程块（共 N 块），每块 32 线程处理该目标的 16 个 Sobol 种子。块内 16 条 lane 并行 LM 迭代后通过共享内存完成候选选择，全部计算局部化于单个 SM 内，无跨块通信开销。

### 6. 网格（Grid）
- **英文**：Grid
- **解释**：一次核函数启动时所有线程块的集合。Grid 维度定义了并行的"粗粒度"层——有多少个独立的任务块。
- **本文用法**：Grid 维度 = N（目标数），实现"每目标一块"的一对一映射。这种规则映射消除了动态负载均衡逻辑，所有块的工作量完全均匀，GPU 时间随 N 严格线性增长。

### 7. 共享内存（Shared Memory）
- **英文**：Shared Memory
- **解释**：位于 SM 片上的高速暂存器（SRAM），同一线程块内所有线程均可访问。延迟约 20--30 个时钟周期，远低于全局内存（HBM/DRAM，约 300--800 周期）。容量有限，Ada Lovelace 架构每 SM 约 100 KB（可配置为 48 KB 共享内存 + 剩余 L1 缓存）。
- **本文用法**：候选解数组 `s_cand[16][16]` 存储在共享内存中，16 条 lane 各自写入自己的候选解后经 `__syncthreads()` 同步，由 lane 0 在共享内存内完成三级层次化选择，全程零全局内存访问。总占用 2064 bytes，不到 48 KB 上限的 5\%。

### 8. 常量内存（Constant Memory）
- **英文**：Constant Memory
- **解释**：GPU 上一块只读内存区域，通过专用常量缓存加速访问。当一个经线内所有线程读取同一地址时，常量缓存通过广播总线在单周期内向全部 32 线程广播该值——相当于"零延迟"广播读取。Ada Lovelace 架构提供 48 KB 常量缓存。
- **本文用法**：将 UR10 的连杆偏移矩阵、关节轴方向、关节限位等编译期确定的运动学参数（共约 2 KB）存入 `__constant__` 内存。所有线程块在 FK 计算中频繁读取关节轴方向——广播总线保证每次读取仅消耗一个时钟周期。

### 9. Bank 冲突（Bank Conflict）
- **英文**：Bank Conflict
- **解释**：共享内存被划分为 32 个 bank（每 bank 宽度 4 bytes）。同一经线内若两个或以上线程在同一时钟周期访问同一 bank 的不同地址，将发生 bank 冲突——这些访问被串行化，吞吐下降。无冲突的条件是：相邻线程访问相邻 4-byte 单元，或地址跨度为 32 的整数倍（使访问落在不同 bank）。
- **本文用法**：候选解数组采用列步长 kCandidateStride=16，相邻 lane 写入同字段时地址偏移 $16\times8=128$ bytes = 32 个 bank 宽度——恰好跨过全部 32 个 bank 后回到同一 bank，但此时访问的是不同 phase（4-byte 粒度），不触发冲突。PTX 汇编确认 bank 冲突为零。

### 10. 寄存器溢出（Register Spill）
- **英文**：Register Spill
- **解释**：GPU 寄存器文件容量有限（Ada Lovelace 每 SM 65536 个 32-bit 寄存器）。当编译器发现线程所需寄存器数量超过硬件限制时，会将部分变量"溢出"到片外 L1 缓存或局部内存——这些位置延迟远高于寄存器，严重影响性能。
- **本文用法**：无限制编译时每线程 194 寄存器，零溢出。人工限制为 160 时开始溢出 216 bytes（load）+ 212 bytes（store），限制为 128 时溢出量增至 568 + 740 bytes，对应性能明显退化。194 为当前算法逻辑的寄存器需求下限。

### 11. 占用率（Occupancy）
- **英文**：Occupancy
- **解释**：SM 上活跃经线数占理论最大经线数的比例。高占用率有助于隐藏内存访问延迟——当一个经线等待数据时，SM 可切换执行另一经线。但占用率并非越高越好：寄存器密集型核函数（如本文）往往以较低占用率换取每线程更多寄存器。
- **本文用法**：每线程 194 寄存器，每经线 6208 寄存器，每 SM 最多驻留 10.5 经线，理论占用率约 44\%。该中等占用率表明本核函数为计算密集型——瓶颈在于 FP64 管线发射延迟而非访存延迟，因此提高占用率收益有限。

### 12. PTX
- **英文**：Parallel Thread Execution
- **解释**：CUDA 编译器（nvcc）生成的中间汇编语言，介于高级 C/C++ 源码与 GPU 机器码（SASS）之间。PTX 可跨 GPU 代际移植，在驱动加载时由 JIT 编译器翻译为目标 GPU 的机器码。分析 PTX 指令可精确统计寄存器用量、共享内存 bank 冲突、指令类型分布。
- **本文用法**：通过 `--keep-device-functions` 编译选项导出 PTX 汇编，定量确认：每线程 194 寄存器、共享内存 bank 冲突为零。这些微观指标直接支撑了"计算密集型"的架构分类。

### 13. SM / 流式多处理器（Streaming Multiprocessor）
- **英文**：Streaming Multiprocessor
- **解释**：GPU 的基本计算单元，内部包含 CUDA 核心、Tensor 核心、寄存器文件、L1 缓存/共享内存、经线调度器。一块 GPU 芯片包含多个 SM（如 RTX 4060 Laptop GPU 有 24 组 SM）。所有线程块最终被调度到各 SM 上执行。
- **本文用法**：24 组 SM 是本文所有实验的硬件基础。每 SM 可驻留约 5.3 个线程块（每块 2 经线 × 32 线程），因此 GPU 可同时并发处理约 127 个目标的 IK 求解。

### 14. Ada Lovelace
- **英文**：Ada Lovelace Architecture
- **解释**：NVIDIA 于 2022 年发布的 GPU 微架构（对应 GeForce RTX 40 系列），计算能力版本 SM 8.9。关键参数包括：FP32 吞吐为 FP64 的 64 倍（前者每 SM 每周期 128 FMA，后者仅 2 FMA）、每 SM 128 KB L1/共享内存、48 KB 常量缓存、支持第四代 Tensor Core。
- **本文用法**：实验平台 RTX 4060 Laptop GPU 基于 Ada Lovelace。该架构 FP32:FP64 = 64:1 的巨大吞吐比是后续混合精度优化的硬件动机——将雅可比和 Hessian 迁移至 FP32 可望获得数量级的吞吐增益。

### 15. FP64 / FP32（双精度/单精度浮点）
- **英文**：Double Precision (64-bit) / Single Precision (32-bit) Floating Point
- **解释**：IEEE 754 标准定义的两种浮点格式。FP64 提供约 15--16 位有效十进制数字，FP32 提供约 6--7 位。科学计算通常依赖 FP64 的累计精度，但 GPU 上 FP64 硬件单元数量远少于 FP32。
- **本文用法**：默认采用全 FP64 精度保证 IK 收敛可靠性。消融实验证实单种子 K=1 时若使用全 FP32，收敛概率进一步恶化。文中将 FP32 雅可比 + FP64 线性求解的混合精度模式列为后续首要加速方向。

### 16. H2D / D2H 传输
- **英文**：Host-to-Device / Device-to-Host Transfer
- **解释**：主机（CPU 端内存）与设备（GPU 显存）之间的数据传输。H2D 将输入数据（如目标位姿、种子）从 CPU 内存拷贝至 GPU 显存；D2H 将计算结果从 GPU 显存回读至 CPU 内存。传输通过 PCIe 总线进行，带宽远低于 GPU 显存带宽，是常见的性能瓶颈。
- **本文用法**：$N=1000$ 时 H2D 传输（目标+种子上传）占总时间的 0.20\%（0.550 ms），D2H 传输（最优解回读）仅占 0.04\%（0.097 ms）。二者之和不足 GPU 总时间的 0.25\%，表明传输不是瓶颈——计算本身是主要耗时项。

### 17. CUDA 图（CUDA Graph）
- **英文**：CUDA Graph
- **解释**：CUDA 提供的一种将一组操作（核函数启动、内存拷贝等）预定义为图结构并批量提交的机制。图的优势在于消除每次单独启动的 CPU 端调度开销——图只需定义一次，后续重放时 GPU 自主按依赖关系执行全部操作。
- **本文用法**：本方法不使用 CUDA Graph（单核函数启动已消除调度开销），而对比方法 cuRobo 在 `curobo-graph` 模式下依靠 CUDA Graph 管理其多阶段流水线（粒子初始化→评估→L-BFGS 更新）。实验表明，即使开启 CUDA Graph，cuRobo 在 $N\le1000$ 时的多阶段流水线调度成本仍可观测。

### 18. CUDA Event API
- **英文**：CUDA Event API
- **解释**：CUDA 提供的高精度 GPU 端计时机制。通过在 GPU 流中插入起止 event，可测量两点之间 GPU 实际执行耗时（以微秒为单位），排除 CPU 端开销。函数 `cudaEventElapsedTime()` 返回 event 之间的时间差。
- **本文用法**：所有吞吐量和 GPU 时间测量均使用 CUDA Event API，排除首轮预热和内存分配时间，30 次重复取均值。这确保了计时数据的准确性——测量的是 GPU 流实际工作时间而非端到端延迟。

### 19. Nsight Compute（NCU）
- **英文**：NVIDIA Nsight Compute
- **解释**：NVIDIA 官方 GPU 核函数性能分析工具，可采集 SM 吞吐率、DRAM/L1/L2 带宽、占用率、经线发散率、共享内存 bank 冲突等详细硬件性能计数器，帮助开发者定位核函数的精确瓶颈。
- **本文用法**：文中第 5 节（结论）将 Nsight Compute 全量性能计数采样列为后续工作，表明当前对微架构的分析主要基于 PTX 静态汇编信息和理论推算（寄存器数、bank 冲突），尚未通过 NCU 获取动态硬件计数器数据。

### 20. 广播总线（Broadcast Bus）
- **英文**：Broadcast Bus
- **解释**：GPU SM 内部连接常量缓存与执行单元的一条专用数据通路。当同一经线内全部线程读取常量内存中同一地址的值时，该值通过广播总线在单周期内同时送达全部 32 个线程——这是一个近乎"零延迟"的广播操作。
- **本文用法**：UR10 关节轴方向等频繁读取的运动学参数存入常量内存后，FK 计算中每次读取仅一个时钟周期即可传入全部线程——这对需要重复读取参数的 20 次 LM 迭代累积效应显著（$20\times6\times32=3840$ 次广播读取/target，均在单周期内完成）。

### 21. 线程同步（__syncthreads()）
- **英文**：Thread Block Synchronization
- **解释**：CUDA 内置函数，在核函数中作为同步屏障——调用点处所有块内线程必须全部到达后才能继续执行后续指令。用于协调块内线程间通过共享内存的数据交换。
- **本文用法**：16 条 lane 各自将 LM 迭代结果写入共享内存后，调用 `__syncthreads()` 确保全部写入完成，然后 lane 0 开始扫描全部候选解进行层次化选择。这个单次同步是块内协作的唯一开销点——在 16 个候选写入完成前不开始选择。

### 22. 计算密集型 v.s. 延迟隐藏型
- **英文**：Compute-bound v.s. Latency-bound
- **解释**：GPU 核函数瓶颈分类中的两种典型类型。计算密集型受限于算术单元吞吐（指令发射速率），增加占用率无助于隐藏指令延迟；延迟隐藏型受限于内存访问延迟，高占用率可通过经线切换掩盖访存等待。分类取决于每线程的算术密集度（FLOP/byte）。
- **本文用法**：44\% 中等占用率 + 零 bank 冲突 + 极少全局内存访问 表明本核函数为计算密集型——每线程 194 寄存器全部用于寄存器级高斯消元和雅可比组装，FP64 标量指令的发射延迟是吞吐量的硬上限。这意味着优化方向不是数据搬运，而是降低单迭代 FP64 运算量。

## 二、机器人运动学领域

### 23. 逆运动学（IK）
- **英文**：Inverse Kinematics
- **解释**：已知机械臂末端期望位姿（位置+姿态），反求各关节角的计算问题。对 6-DOF 串联机械臂，这是一组高度非线性方程，通常无解析解，需借助迭代数值优化方法求解。IK 是运动规划、抓取生成和轨迹优化的基础计算原语。
- **本文用法**：全文的核心求解问题。将 $N$ 个目标位姿批量求解对应关节角——每个目标独立为 6 维非线性最小二乘问题，$N$ 个目标构成批量并行调度场景。

### 24. 正运动学（FK）
- **英文**：Forward Kinematics
- **解释**：已知关节角，计算末端执行器位姿的正向映射。对串联机械臂，FK 通过从基座到末端的逐连杆齐次变换矩阵连乘完成，是确定性且解析的计算。
- **本文用法**：FK 是 LM 迭代中评估候选解的核心函数，也是目标位姿生成的方式（随机关节角→FK→物理可达目标）。本文设计的融合 FK 在单次前向传播中同步输出末端位姿、各关节世界位置和转轴，为后续解析雅可比组装提供全部几何量。

### 25. 雅可比矩阵 / 解析雅可比
- **英文**：Analytical Jacobian
- **解释**：雅可比矩阵 $J$ 描述关节角增量 $\Delta q$ 到末端位姿增量 $\Delta x$ 的线性映射：$\Delta x=J\Delta q$，其元素为末端位姿对各关节角的偏导数。解析雅可比利用关节转轴 $z_i$ 和关节位置 $p_i$ 直接通过几何关系（叉积公式）组装 $J$，不需要对 FK 做数值扰动。
- **本文用法**：单次融合 FK 输出 $p_i$, $z_i$ 后，$6\times6$ 雅可比由 6 次叉积（各 6 FLOP）组装完成——替代了数值差分方案每迭代 12 次额外 FK 调用（每次约 800 FLOP）。精度从差分截断 $10^{-6}$ 提升至机器精度 $10^{-16}$。

### 26. 数值差分雅可比
- **英文**：Finite-Difference Jacobian
- **解释**：通过 $J_{ij}\approx(\mathrm{FK}(q+\delta e_j)-\mathrm{FK}(q-\delta e_j))/(2\delta)$ 对小扰动 $\delta$ 做二点中心差分来近似雅可比元素。通用但计算量大（每迭代需 $2\times6=12$ 次额外 FK 调用），且受差分截断误差限制（$\mathcal{O}(\delta^2)$，典型 $\delta=10^{-6}$ 时截断误差约 $10^{-6}$）。
- **本文用法**：作为解析雅可比的对照方案。文中定量指出数值差分的截断误差（$10^{-6}$）已接近 Strict 阈值量级，可能将收敛解误判为失败；而解析方案的机器精度（$10^{-16}$）完全消除这一风险。这是本文选择解析组装的核心动机之一。

### 27. URDF
- **英文**：Unified Robot Description Format
- **解释**：机器人学中描述机械臂几何、运动学和动力学参数的 XML 标准格式。由 ROS（Robot Operating System）社区定义和维护，包含连杆长度、关节类型、轴方向、质量、惯性张量等信息。
- **本文用法**：UR10 官方 URDF 文件来自 Universal Robots GitHub 仓库，经解析提取出连杆偏移矩阵、关节轴方向和关节限位值——这些参数被固化编译为 CUDA 常量内存内容。

### 28. 关节限位（Joint Limits）
- **英文**：Joint Limits
- **解释**：机械臂各关节的物理旋转范围（最小/最大角度）。UR10 肩部关节约 $\pm360^\circ$，腕部关节 $\pm180^\circ$。超出限位的解在物理上不可行，必须被 IK 算法排除或惩罚。
- **本文用法**：通过二次障碍函数 $\Phi_{\mathrm{limit}}$ 惩罚接近限位的候选解（margin 0.087 rad $\approx5^\circ$，权重 $w_{\mathrm{limit}}=0.03$），在线性系统右端项中加入障碍函数梯度 $\nabla\Phi_{\mathrm{limit}}$，使 LM 迭代自动远离限位边界。

### 29. tool0
- **英文**：tool0 Frame
- **解释**：UR 系列机械臂的标准末端参考坐标系，位于手腕法兰盘中心（不含末端执行器）。URDF 模型中使用 `tool0` 命名该坐标系。它是正运动学计算的终点——FK($q$) 返回 tool0 相对于基座的位姿。
- **本文用法**：目标位姿定义为 tool0 系，融合 FK 的最终输出为 $T_{\mathrm{ee}}=T_{\mathrm{wrist3\_to\_tool0}}$（腕 3 关节到 tool0 的固定变换 × 前向累积变换）。tool0 是本 IK 问题的求解目标系。

### 30. 齐次变换矩阵 & $\SE(3)$
- **英文**：Homogeneous Transformation Matrix / Special Euclidean Group $\SE(3)$
- **解释**：$4\times4$ 矩阵，左上角 $3\times3$ 旋转矩阵描述姿态，右上角 $3\times1$ 平移向量描述位置，末行恒为 $[0,0,0,1]$。所有这样的矩阵构成特殊欧几里得群 $\SE(3)$，描述三维空间中刚体的所有可能位姿。
- **本文用法**：FK 计算以 $4\times4$ 齐次变换矩阵的累积乘法实现（初始 $T=I_4$，每连杆左乘连杆偏移和关节旋转矩阵）。目标位姿 raw 文件存储为行优先 $4\times4$ double 精度矩阵（每目标 16 个双精度浮点数）。

### 31. 旋转向量 / 罗德里格斯公式
- **英文**：Rotation Vector / Rodrigues' Rotation Formula
- **解释**：Rodrigues 公式将"绕单位轴 $a$ 旋转角度 $\theta$"的参数化描述转化为 $3\times3$ 旋转矩阵：$R=I+\sin\theta[a]_\times+(1-\cos\theta)[a]_\times^2$。旋转向量 $\theta a$（长度=旋转角，方向=转轴）是 $\SO(3)$ 的一种紧凑表示，姿态误差常用对数映射 $\log(R)^\vee$ 将其转为旋转向量。
- **本文用法**：融合 FK 算法中绕关节轴 $i$ 旋转角度 $q_i$ 通过 Rodrigues 公式计算旋转矩阵，再填入 $4\times4$ 齐次矩阵的旋转子块。姿态误差 $e_R=\log(R^\star{^\top}R_{\mathrm{ee}})^\vee$ 将旋转矩阵误差映射为旋转向量，作为 LM 优化器姿态项。

### 32. 自由度（DOF）
- **英文**：Degree of Freedom
- **解释**：描述机械系统独立运动参数的数量。6-DOF 串联机械臂指 6 个独立旋转关节，可达到其工作空间内任意位姿（位置 3 自由度 + 姿态 3 自由度）。6-DOF 是最小的可实现三维空间全位姿控制的自由度数量。
- **本文用法**：UR10 为 6-DOF 全旋转关节串联机械臂，$q\in\mathbb{R}^6$，雅可比和 Hessian 均为 $6\times6$ 方阵。矩阵规模的"小"（6×6）是本文设计决策的根本出发点——如此小的规模使寄存器级高斯消元成为可能。

### 33. 奇异位形
- **英文**：Singularity / Singular Configuration
- **解释**：机械臂处于某关节角组合时，雅可比矩阵秩下降（不满秩），某些方向的末端运动在瞬时无法实现——无限大的关节速度也无法驱动末端沿该方向移动。奇异位形附近雅可比条件数极大，导致 LM/Newton-Raphson 类算法数值不稳定。
- **本文用法**：6-DOF 串联机械臂在关节限位和奇异位形附近存在"多解性和可解性退化问题"，这正是多种子策略的必要性所在——单种子初始值若落在奇异位形附近，算法可能发散至不可行解。

## 三、数值计算与优化领域

### 34. Levenberg-Marquardt 算法（LM）
- **英文**：Levenberg-Marquardt Algorithm
- **解释**：求解非线性最小二乘问题的经典迭代优化算法，介于梯度下降（一阶）与 Gauss-Newton（二阶）之间。通过阻尼因子 $\lambda$ 插值调节搜索方向——$\lambda$ 大时趋近梯度下降（稳定但慢），$\lambda$ 小时趋近 Gauss-Newton（快速但可能不稳定）。每步求解正规方程 $(J^\top J+\lambda I)\Delta q=-J^\top e$。
- **本文用法**：每个 Sobol 种子独立执行最多 60 次 LM 迭代。关键创新在于摒弃传统 acceptance-rejection 分支——无论 cost 升降，总是接受新候选解，仅调节 $\lambda$（cost 下降时 $\lambda\leftarrow0.5\lambda$，上升时 $\lambda\leftarrow2\lambda$），确保 32 线程经线内无分支发散。

### 35. Sobol 序列 / 低差异序列
- **英文**：Sobol Sequence / Low-Discrepancy Sequence
- **解释**：一种准随机（quasi-random）数序列，在超立方体内生成比纯随机序列更均匀分布的点。与伪随机数相比，Sobol 序列对高维空间的覆盖更均匀——没有聚集区也没有空洞区。属于低差异（low-discrepancy）序列家族。
- **本文用法**：$K=16$ 组 Sobol 种子作为 LM 优化器的多起点初始值。消融实验揭示：$K$ 从 16 降至 1 后成功率从 0.954 暴跌至 0.522——Sobol 种子在关节空间中的均匀散布是成功率的决定性来源，16 个低差异起点几乎完全覆盖了非凸目标函数的可行解盆地。

### 36. 高斯消元法（含部分主元）
- **英文**：Gaussian Elimination with Partial Pivoting
- **解释**：求解线性方程组 $Ax=b$ 的直接法。部分主元策略在每步消去前选择当前列中绝对值最大的元素作为主元（pivot），与当前行交换——提高数值稳定性，避免除以小量导致的精度丧失。对 $6\times6$ 系统仅需 6 次主元消去。
- **本文用法**：LM 每步的正规方程 $(J^\top J+\lambda I)\Delta q=-J^\top e$ 为 $6\times6$ 对称正定系统，在寄存器内通过自编的高斯消元求解（非 cuBLAS/cuSOLVER 库——6×6 规模下库调用开销大于计算本身）。所有中间变量保持在寄存器中，零全局内存访问。

### 37. 阻尼因子（Damping Factor）
- **英文**：Damping Factor $\lambda$
- **解释**：LM 算法中控制搜索步长和方向的核心参数。$\lambda J^\top J$ 的加入使正规方程系数矩阵的正定性增强，$\Delta q$ 的模被压缩——迭代更保守但更稳定。每次迭代完成后根据实际 cost 变化调整 $\lambda$ 是 LM 算法的灵魂。
- **本文用法**：$\lambda$ 初始值 0.01，范围 $[10^{-6}, 0.5]$。自适应策略简化：cost 下降时 $\lambda\leftarrow0.5\lambda$（向 Gauss-Newton 加速），cost 上升时 $\lambda\leftarrow2\lambda$（向梯度下降收缩步长）。始终接受新解的无分支策略消除了传统 LM 的"尝试-拒绝-回滚"的经线发散成本。

### 38. 障碍函数 / 限位障碍
- **英文**：Barrier Function / Limit Barrier
- **解释**：约束优化中的惩罚方法——在目标函数中添加一项在可行域边界处趋于无穷的光滑函数，迫使优化器远离约束违反区域。二次障碍函数形式 $\phi(q)=\max(0,m-(q-q_{\min}))^2+\max(0,m-(q_{\max}-q))^2$，在 margin $m$ 范围内施加二次惩罚。
- **本文用法**：$\Phi_{\mathrm{limit}}=\sum_{j=0}^5\phi(q_j)$ 为 6 个关节的障碍函数之和，margin $m=0.087$ rad（约 $5^\circ$）。梯度 $\nabla\Phi_{\mathrm{limit}}$ 加入正规方程右端项，在每次 LM 迭代中自动推开逼近限位的解。权重 $w_{\mathrm{limit}}=0.03$ 经手动调优平衡精度与限位安全。

### 39. Acceptance-Rejection 机制
- **英文**：Acceptance-Rejection Mechanism
- **解释**：传统 LM 算法中每步计算尝试步 $\Delta q$ 后评估新 cost——若 cost 下降则接受 $\Delta q$ 并降低 $\lambda$；若 cost 上升则拒绝 $\Delta q$、回滚 $q$ 并增大 $\lambda$ 后重新求解正规方程。该分支对不同种子的迭代轨迹差异导致经线内线程执行路径分化（warp divergence）。
- **本文用法**：明确摒弃该机制——总是接受 trial 解，仅调节 $\lambda$ 用于下一步。这牺牲了单步的 cost 单调下降保证（理论上可能出现 cost 连续上升的情况），但实践表明在 $6\times6$ 小规模 IK 问题中不影响最终收敛质量，却消除了代价高昂的经线发散。

### 40. 收敛判定
- **英文**：Convergence Criterion
- **解释**：决定迭代优化算法何时停止的判据。常用准则包括：目标函数变化量 $|f_{k+1}-f_k|<\varepsilon$、参数变化量 $\|\Delta q\|<\varepsilon$、梯度范数 $\|\nabla f\|<\varepsilon$，或在 IK 场景中直接检测位姿误差是否满足阈值。
- **本文用法**：直接检测位置误差 $\|e_p\|<5$ mm 且姿态误差 $\|e_R\|<1^\circ$（Strict 阈值），满足则提前退出迭代。这一判据直接对应应用层需求——不需要最优解，只需要满足工程精度的可行解。提前退出的设计减少了不必要的迭代轮数（实际平均约 20 次，远低于上限 60 次）。

### 41. L-BFGS 优化器
- **英文**：Limited-memory Broyden–Fletcher–Goldfarb–Shanno
- **解释**：拟牛顿法的一种实现，通过维护有限长度（通常 5--15）的梯度差和参数差历史来近似 Hessian 矩阵的逆，存储开销为 $\mathcal{O}(nd)$（$d$ 为记忆长度），兼具二阶收敛速度和低内存需求。是机器学习中广泛使用的优化算法。
- **本文用法**：cuRobo 的核心优化器，其默认配置 $K=1$（单种子 L-BFGS）局部收敛能力优于本文的单种子 LM——同等单种子条件下 cuRobo Strict SR 为 0.830--0.880，本方法仅 0.450--0.522。当 cuRobo 提升至 $K=16$ 时 Strict SR 达 0.988，为全文质量天花板。

### 42. 多起点策略
- **英文**：Multi-Start Strategy
- **解释**：从多个不同初始点独立运行同一下降算法，最终选择最优结果。用于减轻非凸优化中陷入局部极小值的风险——不同起点落入不同收敛盆地，增加至少一个起点收敛至全局最优的概率。
- **本文用法**：$K=16$ 个 Sobol 低差异序列种子构成的多起点策略是本文方法成功率的核心来源。消融实验定量证明：将 $K$ 降至 1 后成功率从 0.954 暴跌至 0.522，$p95$ 误差从 4.6 mm 飙升至 685 mm——成功率几乎完全来源于多起点策略而非 LM 优化器自身的收敛能力。

### 43. 正规方程
- **英文**：Normal Equation
- **解释**：线性最小二乘问题 $\min\|J\Delta q+e\|^2$ 的解析解条件：$J^\top J\Delta q=-J^\top e$。在 LM 框架中扩展为 $(J^\top J+\lambda I)\Delta q=-J^\top e$。正规方程将 $m\times n$ 过定系统转化为 $n\times n$ 方阵系统（本文 $n=6$），但系数矩阵条件数变为原 Jacobian 的平方——对小规模良态系统影响可忽略。
- **本文用法**：每步 LM 迭代组装正规方程，$H=J^\top J+\lambda I$ 及 $g=J^\top e$，然后在寄存器内通过高斯消元直接求解 $\Delta q$。由于维数仅 6，矩阵条件数的平方放大效应极弱——正则化项 $\lambda I$ 进一步保证了正定性。

### 44. 帕累托前沿
- **英文**：Pareto Frontier
- **解释**：多目标优化中，无法在不恶化至少一个目标的情况下改进任一目标的解的集合。在追求"高质量 + 高吞吐"的场景中，帕累托前沿描述了可达的"质量-速度"最优权衡线——前沿之外的方案可同时改进两个目标。
- **本文用法**：三方对比（cuRobo K=16 / 本方法 K=16 / cuRobo K=1）构成清晰的帕累托前沿：cuRobo K=16 为质量天花板（SR 0.988），本方法 K=16 为吞吐优先且满足 Strict 阈值（SR 0.954），cuRobo K=1 为极端吞吐但质量不可用（SR 0.840）。本方法的定位由此明确——不是优化器性能的超越，而是在满足工程精度阈值前提下的吞吐最大化。

### 45. 消融实验
- **英文**：Ablation Study
- **解释**：系统性地移除或关闭方法中的某一组件，观察性能变化，从而定量衡量该组件对整体性能的贡献。消融实验是机器学习/系统中验证"每个设计决策确实必要"的标准方法。
- **本文用法**：关键消融为将 Sobol 种子数 $K$ 从 16 降至 1，保持其他全部参数不变。实验揭示：（1）成功率几乎完全来源于多起点策略；（2）以约 35\% 的速度代价换取 $>100\%$ 的成功率提升；（3）核函数启动次数与 $K$ 无关（恒为 1），这一结构属性是多起点策略"低代价"的根本原因。

### 46. Amdahl 定律
- **英文**：Amdahl's Law
- **解释**：并行计算中的基本定律：加速比受限于不可并行化部分的比例。若串行分量占比为 $s$，$p$ 个处理器的理论最大加速比为 $1/(s+(1-s)/p)\le 1/s$。该定律揭示了"固定问题规模下并行化收益递减"的本质规律。
- **本文用法**：吞吐量从 $N=100$ 的 $1.50\times10^4$ 渐近收敛至 $N=1000$ 的 $1.82\times10^4$（仅提升 21\%），符合 Amdahl 定律——lane 0 串行候选选择（约 0.005 ms/target）构成不可并行的串行分量，限制了进一步加速的上限。

### 47. 截断误差 v.s. 机器精度
- **英文**：Truncation Error v.s. Machine Precision
- **解释**：数值微分中的截断误差来源于用有限差分近似无限小导数的理论误差（二点中心差分误差 $\mathcal{O}(\delta^2)$，$\delta=10^{-6}$ 时约 $10^{-6}$）。机器精度（machine epsilon）是浮点格式能表示的最小相对间隔——FP64 约 $2.2\times10^{-16}$，代表舍入误差的量级。
- **本文用法**：数值差分雅可比的截断误差（$10^{-6}$）与 Strict 阈值（5 mm/$1^\circ$）处于同一量级——可能将已经收敛的解误判为失败。解析雅可比的误差降至机器精度 $10^{-16}$，比截断误差低 10 个数量级，完全消除了误差混淆收敛判定的风险。这是本文选择解析雅可比组装的核心精度论据。
