### P0-1. 删除或降级“吞吐优势完全来源于单核函数融合”的绝对表述

#### 当前问题

论文第 4.2 节存在类似表述：

```text
该吞吐优势完全来源于单核函数融合对多阶段流水线固定调度成本的消除。
```

这个判断过强。cuRobo-Graph-K16 的吞吐较低，不只因为 kernel launch 或多阶段调度，也可能因为：

- cuRobo 内部优化流程更复杂；
- cuRobo 追求更高成功率和更低残差；
- cuRobo 的粒子群 / L-BFGS 流水线计算量更大；
- 两者单 seed 的计算复杂度并不相同；
- CUDA Graph 虽减少 launch，但不能等同于无调度成本；
- 本文 OPT4C 的固定结构 LM 路径本身更轻量。

#### 修改要求

将“完全来源于”改为“主要相关于 / 主要来自于 / 部分来自于”。

推荐替换段落：

```text
该吞吐优势主要来自单核函数融合减少阶段间全局内存中转和 host-device 同步，同时也与本文固定结构 LM 的较轻量计算路径有关。由于 cuRobo-Graph-K16 追求更高成功率和更低残差，其内部粒子初始化、评估与 L-BFGS 优化流程更复杂，因此二者的吞吐差异不应仅归因于 kernel launch 或调度开销。
```

#### 验收标准

- [ ] 全文不再出现“完全来源于单核函数融合”；
- [ ] 不再把 cuRobo-K16 较慢单一归因于 launch / 调度；
- [ ] 明确承认算法复杂度和精度目标也影响吞吐；
- [ ] 保留本文“单 kernel fusion 减少中间同步”的贡献，但不过度解释。

### P0-2. 修改 “cuRobo-K1 质量不可用” 的表述

#### 当前问题

表 6 或正文中存在类似定位：

```text
cuRobo K=1 为极端吞吐但质量不可用
```

该表述不够严谨。cuRobo-K1 在 N=1000 时：

```text
Strict SR = 0.840
all-sample p95 = 88.67 mm
success-sample p95 = 0.28 mm
```

这说明 cuRobo-K1 的失败尾部较重，但成功样本精度非常高。不能简单写成“质量不可用”。

#### 修改要求

将“质量不可用”替换为以下之一：

```text
全样本质量受失败尾部影响
```

或：

```text
无重试 Strict 输出不稳定
```

或：

```text
失败尾部较重
```

推荐表 6 “定位”列修改：

| 原表述 | 建议表述 |
|---|---|
| 极端吞吐（质量不可用） | 极端吞吐（失败尾部较重） |
| 质量不可用 | 全样本质量受失败尾部影响 |
| 默认单种子质量差 | 默认单种子 Strict 稳定性不足 |

#### 验收标准

- [ ] 全文不再出现“cuRobo-K1 质量不可用”；
- [ ] 保留 cuRobo-K1 全样本 p95 被失败尾部拉高的事实；
- [ ] 同时承认 cuRobo-K1 成功样本 p95 很低；
- [ ] 不贬低 cuRobo 的成功样本精度。

### P0-3. 收敛“有效吞吐量”分析逻辑

#### 当前问题

论文当前写法大致是：

```text
cuRobo-K1 的有效吞吐仍高于本文方法，但本文方法一次性高成功率具有工程优势。
```

这个逻辑可以成立，但需要更严密。因为从表 6 看：

```text
cuRobo-K1 effective throughput = 61004 targets/s
OPT4C-K16 effective throughput = 17387 targets/s
```

仅以 `throughput × Strict SR` 衡量，cuRobo-K1 仍远高于 OPT4C-K16。因此不能用“有效吞吐”直接证明本文工程优势。

#### 修改要求

推荐替换为：

```text
若仅以 throughput × Strict SR 衡量，cuRobo-Graph-K1 仍具有更高有效吞吐；但该指标未反映失败目标在规划管线中的重采样、回退或轨迹修补代价。对于要求单次 batch 输出高比例 Strict 解、且不希望引入额外回退逻辑的规划前端，OPT4C-K16 的一次性成功率更具工程可控性。
```

#### 验收标准

- [ ] 承认 cuRobo-K1 的 `throughput × SR` 更高；
- [ ] 不用有效吞吐强行证明 OPT4C 全面更优；
- [ ] 工程优势限定在“一次性高成功率 / 少回退 / 规划前端可控性”；
- [ ] 逻辑不自相矛盾。

### P0-7. 轨迹实验补充 jump ratio，并进一步强调局限性

#### 当前问题

当前轨迹实验已经使用 wrap 差分：

```text
∆q = atan2(sin(q_t − q_{t−1}), cos(q_t − q_{t−1}))
```

并给出：

```text
原始 best p95(∆q) = 5.44–5.61 rad
smoothness rerank p95(∆q) = 3.48–3.80 rad
jump count = 718–778
jump threshold = 0.5 rad
```

但没有给 jump ratio。每类轨迹为：

```text
20 条 × 50 点
相邻间隔数 = 20 × 49 = 980
```

因此 smoothness rerank 后 jump ratio 仍约：

```text
718 / 980 = 73.3%
778 / 980 = 79.4%
```

这说明轨迹连续性仍很差，需要明确作为局限性。

#### 修改要求

在 4.6 节加入：

```text
由于每类轨迹包含 20×49=980 个相邻间隔，smoothness rerank 后 jump ratio 仍约为 73%–79%，说明当前候选级重排序只能降低跳变幅值，不能从根本上保证关节连续性。
```

并在结论或讨论中补充：

```text
因此，本文方法更适合作为独立目标批量 IK 或规划前端候选生成器；若要直接输出连续控制轨迹，需要引入上一时刻解 warm-start、连续性约束或轨迹级优化。
```

#### 验收标准

- [ ] 轨迹实验报告 jump ratio；
- [ ] 明确总相邻间隔数为 980；
- [ ] 结论承认不能直接保证连续控制轨迹；
- [ ] 不把 smoothness rerank 写成解决轨迹连续性的充分方法。
