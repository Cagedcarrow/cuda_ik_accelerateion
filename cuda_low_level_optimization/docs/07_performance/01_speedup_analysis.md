# 960× 加速比分析

> 测试日期: 2026-06-05 | CUDA 13.3.33 | RTX 4060 Laptop GPU

## 加速比总览

CUDA 批处理 IK 求解器相比 CPU KDL 求解器实现了 **~960×** 加速比（纯 DLS IK 求解环节）：

| 求解器 | 时间 | 任务数 | 说明 |
|--------|------|--------|------|
| CPU C++ KDL（单线程） | 6.2 s | 13,104 | 纯 DLS IK: 273 targets × 48 seeds |
| CPU C++ KDL（含4组权重） | ~24.8 s | 52,416 | 273 × 48 seeds × 4 weight schedules |
| GPU CUDA 裸 kernel (CUDA Events) | 5.221 ms | 52,416 | ik_batch_solve 纯计算 |
| **GPU CUDA 论文引用值** | **6.434 ms** | 52,416 | 含 H2D/D2H + multi-kernel 调度 |
| GPU CUDA (单目标) | 0.019 ms | 1 | 单目标裸 kernel 时间 |

## 加速比计算

| 指标 | CPU (KDL C++) | GPU (CUDA) | 加速比 |
|------|--------------|------------|--------|
| 批处理 IK（纯DLS，13,104任务） | 6.2 s | — | — |
| 批处理 IK（52,416任务，4组权重） | ~24.8 s | 6.434 ms | **~3,850×** |
| 批处理 IK（论文对比基线*） | 6.2 s | 6.434 ms | **~960×** |
| 批处理 IK（vs 4线程CPU基线**） | ~6.2 s (4P-core OpenMP估算) | 6.434 ms | **~964×** |
| 单目标求解 | 22.7 ms | 0.024 ms | 946× |
| 平均迭代次数 | 9.2 | 6.7 | 1.37× |
| 碰撞检测（100帧） | ~0.9 s (CPU FCL) | 10.43 μs (ncu实测) | **~86×** |

> \*论文以 CPU 纯 DLS 求解 13,104 任务（6.2s）为基线，与 GPU 批处理 52,416 任务（6.434ms）对比。
> 这一对比虽任务数不对等（GPU做了4倍工作量），但体现了 GPU 的独特优势：
> 增加权重调度方案在 GPU 上几乎零额外开销（并行执行），而在 CPU 上需线性累加。
> 若以相同 52,416 任务对比，加速比约为 3,850×。
>
> \*\*多线程CPU基线基于Amdahl定律估算：IK循环为完美并行段（占比>99%），4线程（4 P-core）OpenMP加速比约4×，
> 52,416任务4线程耗时约6.2s，GPU vs 4线程加速比~964×。详见第5.5节加速比分析。

## 加速来源分析

### 1. 任务级并行 (~273×)

```
CPU:  13,104 个任务串行 → 6.2 s
GPU:  52,416 个 Block 并行 → 6.434 ms
      （273 targets × 48 seeds × 4 weights = 52,416 blocks across launches）
```

### 2. Block 内数据并行 (4~6×)

每个 Block 的 4 个 Warp 分工：

| Warp | 任务 | 并行度 |
|------|------|--------|
| Warp 0 | FK（6 关节循环展开） | ~3× |
| Warp 1 | Jacobian（6 列并行） | 6× |
| Warp 2 | Hessian（36 元素并行） | 6× |
| Warp 3 | LDL^T（Lane 0 串行） | 1× |

### 3. 内存层次优化

- **常量内存广播**: 1,384 bytes 运动学参数，32× 带宽放大
- **共享内存 8 列 padding**: 消除 Bank 冲突（ncu 实测零冲突）
- **寄存器零溢出**: 96 regs/thread，所有中间变量在寄存器中
- **DRAM Throughput 仅 0.16%**: 完全片上执行

### 4. 消除 Kernel Launch 开销

- v2.0 CPU 端: 273×192 = 52,416 次 kernel launch
- v3.0 GPU 端: 273 次 launch（每目标 1 次，含全部 192 个种子×权重组合）
- 单次 launch 调度开销 ~5-10μs → 消除 ~1.0-1.9 ms

## 不同批处理规模的加速比（理论估算）

| 批处理数 | CPU 时间 | GPU 时间 | 加速比 |
|---------|---------|---------|--------|
| 1 | 22.7 ms | 0.23 ms | 99× |
| 10 | 227 ms | 0.38 ms | 597× |
| 50 | 1.14 s | 1.52 ms | 750× |
| 273 | 6.2 s | 6.434 ms | 960× |
| 1000 | 22.7 s | 23.6 ms | 962× |

> 批处理规模越大，GPU 利用率越高，加速比越接近理论极限。

## 性能瓶颈

ncu 实测揭示的性能瓶颈优先级：

1. **`__syncthreads()` 屏障等待 (72.7% stall)** — 每个 DLS 迭代 14 个同步点，4-Warp 协作的结构性代价
2. **FP64 核心数量 (仅 48 个)** — 消费级 GPU FP64:FP32=1:64 的硬件限制
3. **尾部效应** — 273 blocks 在 24 SM 上仅 2.27 waves，最后一波空闲 SM 多
