# cuRobo Quality Audit Round 2：定位 cuRobo pos_p95 异常的具体原因

## 0. 背景

第一轮 UR10 模型一致性审计已经完成：

```text
1. CUDA 与 cuRobo 使用同一份 official UR10 URDF。
2. ur_type=ur10，没有 ur10/ur10e 混用。
3. tool0/flange/wrist_3_link 无 70~110mm 固定 TCP 平移 offset。
4. joint order 一致。
5. 100 个随机 q 的 FK cross-check：
   max pos diff = 0.000336 mm
   max rot diff = 2.94e-05 deg
   max_T_abs_diff = 4.18e-07
```

因此，cuRobo 的 `70~110mm pos_p95_all` 基本不能归因于 URDF、frame、tool offset 或 joint order。

本轮目标：

```text
找出 cuRobo pos_p95_all 很大的具体原因：
A. 是否失败样本拉高 all p95；
B. 是否 target quaternion 输入格式有问题；
C. 是否 cuRobo reported error 与本文 FK 复评 error 不一致；
D. 是否 seed 数 / optimizer 参数不足；
E. 是否目标本身集中在奇异位形、边界或难解区域；
F. 是否 cuRobo 当前配置偏吞吐，不偏 Strict IK 质量。
```

# 5. Step C：Quaternion / target pose 输入审计

虽然 URDF/FK 已一致，但 target pose 输入仍可能有问题。

检查：

```text
1. cuRobo 需要 quaternion 顺序是 wxyz 还是 xyzw；
2. 当前传入 cuRobo 的 quaternion 顺序；
3. target quaternion 是否归一化；
4. rotation matrix determinant 是否接近 1；
5. rotation matrix orthogonality error 是否接近 0；
6. 同一 target 用 wxyz 和 xyzw 两种解释时，姿态差异是多少。
```

对至少 100 个 target 输出：

```text
target_id
q_input_0
q_input_1
q_input_2
q_input_3
assumed_order
quat_norm
det_R
orthogonality_error
rot_diff_if_wxyz_vs_xyzw_deg
target_frame
notes
```

必须额外做一个小实验：

```text
N=100
分别用当前 quaternion 顺序、强制 wxyz、强制 xyzw 跑 cuRobo IK。
比较 Strict SR、pos_p95_all、pos_p95_success_only。
```

输出：

```text
data/results/final_push/curobo_quaternion_audit.csv
```

判断：

```text
如果更换 quaternion 顺序后 cuRobo Strict SR 大幅提升或 pos_p95 大幅下降：
说明之前 cuRobo target pose 输入格式错误，必须重跑全部 cuRobo boundary。

如果两种顺序差异不大：
说明 quaternion order 不是主因。
```

# 12. Root Cause 最终判定规则

## A. failure-tail dominated

满足：

```text
pos_p95_success_only 很小；
pos_p95_all 很大；
reported error 与 reeval error 一致；
quaternion 正确。
```

结论：

```text
cuRobo 成功解精度正常，但失败样本较多，导致 all p95 error tail 大。
```

## B. quaternion/input bug

满足：

```text
更换 quaternion 顺序后 cuRobo 质量明显改善；
或 reported error 与 reeval error 系统性不一致。
```

结论：

```text
当前 cuRobo boundary 需要修正后重跑。
```

## C. seed/config insufficient

满足：

```text
增加 num_seeds 或 optimizer iterations 后 Strict SR 明显提升、pos_p95_all 明显下降。
```

结论：

```text
当前 cuRobo 默认/高吞吐配置未充分调优。
```

## D. throughput-quality tradeoff

满足：

```text
质量配置下 cuRobo 质量提升，但吞吐明显下降。
```

结论：

```text
论文应报告 cuRobo high-throughput 与 quality-tuned 两种配置。
```

## E. hard target distribution

满足：

```text
cuRobo 失败集中在特定 workspace / orientation / near singularity 区域。
```

结论：

```text
本文目标集包含对 cuRobo 当前配置较困难的目标分布。
```

## F. metric mismatch

满足：

```text
cuRobo 自身 success 和本文 Strict success 差异很大；
both_success 样本中 cuRobo 在本文 metric 下误差仍大。
```

结论：

```text
需要在论文中明确 cuRobo internal metric 与本文 Strict metric 不完全一致。
```

## G. unknown

如果无法归因：

```text
标记 unknown，不得强行下结论。
```
