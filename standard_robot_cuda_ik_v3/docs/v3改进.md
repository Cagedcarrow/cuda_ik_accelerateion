# V3 后续改进方案：从随机 MultiSeed 转向稳定收敛盆地覆盖

## 0. 当前阶段结论

### 0.1 已确认事实

当前 V3 排查后得到以下结论：

1. SR 单调性验证正确：

   * Loose ≥ Medium ≥ Strict。
   * 之前 Medium SR 低于 Strict SR 是跨运行随机种子不同导致的偶然结果。

2. 之前 Multi4 / Multi8 的 91% / 93.5% Strict SR 不能作为正式结论使用：

   * 原因是 `np.random.default_rng(SEED)` 在每次调用时重置。
   * 200 个目标实际共享同一组辅助随机 seed。
   * 该结果更像是某组固定 seed bank 恰好适配目标集，而不是稳定的 multi-seed 能力。

3. 当前严格控制变量后，V3-LM-Multi4 真实表现为：

   * Loose SR: 94.0%
   * Medium SR: 90.5%
   * Strict SR: 52.5%

4. 误差诊断显示：

   * Strict 成功样本内部质量较好：

     * pos_p50 = 1.34 mm
     * pos_p95 = 4.31 mm
     * pos_max = 4.85 mm
   * 全部样本长尾严重：

     * pos_p95 = 33.23 mm
     * pos_max = 217.71 mm

### 0.2 核心判断

V3 当前瓶颈不是解析 Jacobian，也不是 LM 局部求解质量，而是：

> seed 对收敛盆地的覆盖能力不足。

换言之：

* LM 在进入正确收敛盆地后，Strict 精度是足够的；
* 但当前 seed 设计无法把足够多目标送进正确收敛盆地；
* 随机 multi-seed 不稳定，不能作为正式论文结论；
* 下一阶段核心不是继续堆 K，而是设计稳定、可复现、目标相关的 seed bank。

# 2. 第一阶段：固定实验基础，消除随机不可比

## 2.1 固定数据集

创建固定目标集：

```text
data/
├── targets_N200_seed42.npy
├── targets_N1000_seed42.npy
├── q_gt_N200_seed42.npy
├── q_gt_N1000_seed42.npy
└── metadata.json
```

要求：

1. 所有目标由合法关节角 `q_gt` 经 FK 生成；
2. `q_gt` 只能用于验证目标可达性和失败分析；
3. 求解器不能直接使用 `q_gt` 作为 seed；
4. N=200 用于快速原型；
5. N=1000 用于稳定性确认；
6. 后续 benchmark 再扩展至 N=100 / 500 / 1000 / 5000 / 10000。

## 2.2 固定 seed bank 文件

所有 seed 必须提前生成并保存，不允许在求解过程中临时隐式随机生成。

目录：

```text
data/seed_banks/
├── seedbank_random_K4_bank00.npy
├── seedbank_random_K4_bank01.npy
├── seedbank_sobol_K8_bank00.npy
├── seedbank_structured_K16_bank00.npy
├── seedbank_targetaware_K16_bank00.npy
└── ...
```

每个 seed bank 形状：

```text
[N, K, 6]
```

即每个 target 独享 K 个 seed。

禁止使用：

```python
np.random.default_rng(SEED)
```

在每个目标内部重复初始化。

推荐写法：

```python
rng = np.random.default_rng(global_seed + target_id * 10007 + seed_id * 97)
```

更推荐：

```python
rng = np.random.default_rng(global_seed)
q_seed = rng.uniform(q_min, q_max, size=(N, K, 6))
```

并一次性保存为 `.npy`。

## 2.3 强制单调性断言

每次实验必须检查：

```python
assert loose_success.sum() >= medium_success.sum()
assert medium_success.sum() >= strict_success.sum()
```

如果断言失败，直接终止实验并输出错误样本。

# 3. 第二阶段：Seed Bank 策略系统比较

当前不要继续只用随机 seed。必须系统比较以下 seed 策略。

## 3.1 策略 A：全局固定 seed bank

### 含义

所有目标共享同一组 K 个 seed。

```text
target_0: seed_0, seed_1, ..., seed_K
target_1: seed_0, seed_1, ..., seed_K
...
```

### 目的

验证“固定 seed bank 是否能够覆盖 UR10 常见构型分支”。

### 优点

* 可复现；
* 实现简单；
* GPU 化容易；
* 对小 K 友好。

### 缺点

* 可能对目标集过拟合；
* 对复杂空间覆盖不足。

## 3.2 策略 B：每目标独立随机 seed

### 含义

每个目标都有独立 K 个随机 seed。

### 目的

验证纯随机搜索的真实统计效果。

### 必须重复

至少 10 个 seed bank：

```text
bank00, bank01, ..., bank09
```

输出：

```text
Strict SR mean ± std
Medium SR mean ± std
pos_p95 mean ± std
```

### 判定

如果 Strict SR 波动超过 10 个百分点，说明纯随机策略不稳定，不能作为论文核心方法。

## 3.3 策略 C：低差异序列 seed

### 方法

使用：

* Sobol sequence；
* Halton sequence；
* Latin Hypercube Sampling。

### 目的

比纯随机更均匀地覆盖 6 维关节空间。

### 设计

将 Sobol 点 `u ∈ [0,1]^6` 映射到关节限位：

```python
q_seed = q_min + u * (q_max - q_min)
```

### 需要测试

|  K | 测试  |
| -: | --- |
|  4 | 基础  |
|  8 | 主测试 |
| 16 | 重点  |
| 32 | 上限  |

## 3.4 策略 D：zero_seed + jitter

### 方法

以 zero seed 为中心添加扰动：

```text
q_seed = zero_seed + Normal(0, σ)
```

测试扰动尺度：

|       σ | 含义   |
| ------: | ---- |
| 0.1 rad | 小扰动  |
| 0.3 rad | 中扰动  |
| 0.6 rad | 大扰动  |
| 1.0 rad | 极大扰动 |

### 目的

验证当前 zero_seed 失败是否可以通过局部扰动修复。

### 预期

如果该策略提升有限，说明失败主要不是局部盆地边界，而是构型分支差异。

## 3.5 策略 E：结构化构型 seed

### 核心思想

UR10 存在典型构型分支：

* shoulder left / right；
* elbow up / down；
* wrist flip / non-flip。

虽然不直接求解析 IK，也可以构造结构化 seed 模板。

### 建议 seed 模板

构造 8 个基础模板：

```text
shoulder_sign ∈ {-1, +1}
elbow_sign    ∈ {-1, +1}
wrist_sign    ∈ {-1, +1}
```

生成：

```text
2 × 2 × 2 = 8 seeds
```

示例模板：

```python
q1 = shoulder_sign * pi/2
q2 = elbow_sign * pi/4
q3 = -elbow_sign * pi/2
q4 = wrist_sign * pi/2
q5 = pi/2
q6 = 0
```

注意：具体数值需要根据 UR10 关节定义调试，不能直接作为最终值。

### 测试组合

|  K | 内容                       |
| -: | ------------------------ |
|  4 | 选择部分结构分支                 |
|  8 | 完整 2×2×2 分支              |
| 16 | 8 结构分支 + 每个分支一个 jitter   |
| 32 | 8 结构分支 + 每个分支 3 个 jitter |

## 3.6 策略 F：目标相关 seed

### 核心思想

seed 不应完全与目标无关。至少可根据目标位置粗略设定 q1、q2、q3。

### F1：q1 由目标水平角初始化

```python
q1_seed = atan2(p_y, p_x)
```

再加：

```text
q1_seed + π
q1_seed - π
```

覆盖 shoulder 分支。

### F2：q2/q3 由平面二连杆近似初始化

将 UR10 简化为肩-肘二连杆平面模型：

```text
r = sqrt(px^2 + py^2)
z = pz - base_height
```

用余弦定理粗略估计 elbow angle。

不要求精确，只要求比随机 seed 更接近合理构型。

### F3：腕部使用目标姿态近似

在 q1/q2/q3 粗略确定后，q4/q5/q6 初始化为：

```text
[0, π/2, 0]
[π/2, π/2, 0]
[-π/2, π/2, 0]
```

### 测试目标

比较目标相关 seed 与 Sobol / 结构化 seed 的 Strict SR。

## 3.7 策略 G：两阶段 seed

### 阶段 1：快速粗求解

用少量迭代，例如 10 次 DLS / LM，快速得到粗解。

### 阶段 2：从粗解附近生成 seed

```python
q_seed_k = q_coarse + jitter_k
```

### 优点

seed 变成 target-dependent。

### 缺点

增加前处理计算，但可 GPU 化。

### 适用

如果目标相关几何 seed 效果不足，再实现两阶段 seed。

# 4. 第三阶段：失败类型分析

仅报告 SR 不够。必须拆解失败原因。

## 4.1 成功判定

对每个目标记录：

```text
pos_err
rot_err
pos_success_loose
rot_success_loose
pos_success_medium
rot_success_medium
pos_success_strict
rot_success_strict
```

## 4.2 失败类型分类

对 Strict 阈值，统计：

| 类型 | 条件            |
| -- | ------------- |
| A  | pos 成功，rot 成功 |
| B  | pos 成功，rot 失败 |
| C  | pos 失败，rot 成功 |
| D  | pos 失败，rot 失败 |

输出表：

| 方法 | A 成功 | B 姿态失败 | C 位置失败 | D 双失败 |
| -- | ---: | -----: | -----: | ----: |

## 4.3 判断优化方向

### 情况 1：主要是 C，位置失败

说明：

* seed 不足；
* λ / step 控制不足；
* 可能陷入错误臂型分支。

优先改：

* 结构化 seed；
* target-aware seed；
* multi-seed K。

### 情况 2：主要是 B，姿态失败

说明：

* orientation error 和 Jacobian 不一致；
* 几何 Jacobian 与 log-map error 定义不匹配；
* 姿态权重不足。

优先改：

* 姿态误差定义；
* body Jacobian / spatial Jacobian 一致性；
* quaternion error 替代 log error；
* 增加姿态权重。

### 情况 3：主要是 D，双失败

说明：

* 收敛盆地没有覆盖；
* seed 远离可行分支；
* 需要结构化 seed / 粗解初始化。

# 5. 第四阶段：LM 本体改进

当前 LM 是简化版，无 rejection。后续需要补完整 step acceptance。

## 5.1 当前问题

简化 LM：

```text
直接 q_new = q + Δq
```

问题：

* loss 变大也接受；
* 容易越过收敛盆地；
* 对 Strict 任务不稳定。

## 5.2 加入 step acceptance

每轮计算：

```python
loss_old = compute_loss(q)
dq = solve_lm_step(q, lambda)
q_candidate = clamp(q + dq)
loss_new = compute_loss(q_candidate)

if loss_new < loss_old:
    q = q_candidate
    lambda *= lambda_down
else:
    reject
    lambda *= lambda_up
```

推荐参数：

```text
lambda_down = 0.5 或 0.7
lambda_up   = 2.0 或 3.0
```

## 5.3 加入 backtracking line search

如果直接步长失败，则测试：

```text
alpha ∈ {1.0, 0.5, 0.25, 0.125}
q_new = q + alpha * dq
```

接受第一个 loss 下降的 alpha。

## 5.4 加入 trust region

限制：

```text
||dq||_∞ ≤ dq_max
```

测试：

```text
dq_max = 0.1 rad
dq_max = 0.2 rad
dq_max = 0.35 rad
dq_max = 0.5 rad
```

## 5.5 关节限位处理

比较三种方式：

| 方法         | 说明                           |
| ---------- | ---------------------------- |
| clamp      | q 超界后直接截断                    |
| reflective | 越界后反射回合法范围                   |
| barrier    | loss 中加入 joint-limit barrier |

优先从 clamp 开始，后续测试 barrier。

## 5.6 LM 参数扫描

对最优 seed bank 策略测试：

| 参数       | 候选                     |
| -------- | ---------------------- |
| λ0       | 1e-4, 5e-4, 1e-3, 5e-3 |
| λ_up     | 2, 3, 5                |
| λ_down   | 0.5, 0.7, 0.8          |
| dq_max   | 0.1, 0.2, 0.35, 0.5    |
| max_iter | 40, 80, 120, 160       |

目标：

* Strict SR 提升；
* pos_p95_all 降低；
* 迭代数不显著增加。

# 7. 第六阶段：GPU MultiSeed 实现

当 Python 原型稳定后，再实现 CUDA 版本。

## 7.1 简单 GPU 方案：Grid(N, K)

每个 target-seed pair 一个 block：

```cpp
dim3 grid(N, K);
dim3 block(128);
ik_lm_multiseed_kernel<<<grid, block>>>(...);
```

每个 block 输出：

```text
q_out[N, K, 6]
loss_out[N, K]
pos_err[N, K]
rot_err[N, K]
success[N, K]
iter_count[N, K]
```

然后第二个 kernel 做 best seed reduction：

```cpp
select_best_seed_kernel<<<N, 128>>>(loss_out, q_out, best_q)
```

## 7.2 优化 GPU 方案：Warp-per-seed

对于 K≤8，可考虑：

```text
one block = one target
one warp = one seed
blockDim = 32 * K
```

例如：

|  K | blockDim |
| -: | -------: |
|  4 |      128 |
|  8 |      256 |

优点：

* 同一 target 的 K 个 seed 在一个 block 内；
* best seed reduction 可在 block 内完成；
* 减少第二个 reduction kernel。

缺点：

* 每个 seed 的寄存器资源减少；
* 实现复杂；
* K=16 时 blockDim=512，可能寄存器压力过大。

建议先实现 Grid(N,K) 简单版，再做 warp-per-seed 优化。

## 7.3 GPU 版必须测的指标

| 指标                 | 含义                 |
| ------------------ | ------------------ |
| GPU stream time    | 核心性能               |
| E2E time           | 工程性能               |
| valid throughput   | 成功解吞吐              |
| kernel launches    | 调度开销               |
| occupancy          | 占用率                |
| regs/thread        | 寄存器压力              |
| local memory spill | 是否溢出               |
| branch divergence  | line search 是否导致分歧 |

## 7.4 GPU 与 Python 对齐验证

在 N=10 / N=50 小样本上比较：

```text
Python LM result
CUDA LM result
pos_err difference
rot_err difference
selected seed id
```

误差允许：

```text

rot error difference < 1e-3 rad
```

# 12. 最终技术判断

当前 V3 的问题不是“多 seed 无效”，而是“随机 seed 设计不稳定”。

正确方向是：

> 从随机 multi-seed 转向结构化、目标相关、可复现的 seed bank，并结合完整 LM step acceptance。

只有当 seed coverage 稳定后，GPU 并行化才有意义。

当前阶段不应急于写“V3 超越 cuRobo”，而应先证明：

1. 哪种 seed 设计能稳定提升 Strict SR；
2. LM 成功样本精度是否稳定；
3. GPU multi-seed 是否能把 K 倍搜索成本并行摊薄；
4. V3 在什么 N 和精度区间能接近或超过 cuRobo-Graph。
