## 一、补充实验概述

根据《改进意见》文档（`docs/改进意见/cuda_ik_paper_revision_instructions.md`）的要求，本轮补充实验覆盖了以下关键问题：

1. **三层计时口径**：End-to-End（H2D+Kernel+D2H）、GPU Stream（CUDA events）、Nsight Systems（kernel launch 数等）
2. **cuRobo CUDA Graph 开/关对比**：原论文仅关闭 CUDA Graph，本文增加了 Graph 开启对照
3. **成功率与有效吞吐**：valid_throughput = raw_throughput × success_rate
4. **多阈值收敛**：Loose(30mm/10°)、Medium(10mm/5°)、Strict(5mm/1°)
5. **误差分布**：位置/姿态误差的 mean、p50、p95、max
6. **统计显著性**：30 次重复实验的 mean/std/p50/p95/min/max
7. **Jacobian 精度验证**：FP32 vs FP64 中心差分 Jacobian 在不同 ε 下的 Frobenius 相对误差

### 2.3 CUDA 改进评价：好 vs 坏

#### ✅ 好的方面（CUDA 改进的优势）

1. **低批量延迟优势明确**：$N=100$ 时 CUDA-Mixed GPU stream 时间（1.24 ms）仅为 cuRobo-Graph（2.60 ms）的 47.7%。单 kernel 零调度开销在低批量下具有结构性优势。

2. **批量扩展性完美线性**：$R^2>0.999$，无任何退化点。吞吐从 $N=500$ 起稳定在 128k–157k t/s 窄区间。这是 1 block/target 映射的结构确定性结果——无子批次划分策略带来的不确定性。

3. **CUDA Graph 价值有限**：A7（直接 launch）与 A8（Graph 回放）差异 <1%，因为单 kernel 方案本身已无 launch 开销可消除。这反过来验证了单 kernel 设计在消除调度开销方面的有效性。

4. **自适应阻尼是收敛率的决定性因素**：A0→A5 将收敛率从 52–83% 恢复至 100%，平均迭代次数下降 59–83%。混合精度在此基础上仅贡献吞吐提升，不损害收敛质量。

5. **Jacobian FP32 精度风险可控**：ε=1e-6 下 FP32 Jacobian 的相对 Frobenius 误差中位数为 4.2×10⁻²（约 2 位有效数字），但由于 LDLᵀ 求解和收敛判定保留 FP64，该 Jacobian 误差未导致最终收敛退化（CUDA-Mixed 在 Medium 阈值下收敛率 ≥0.998）。

6. **Bank 冲突降低 63% 实质有效**：NCU 实测从 3,522 次降至 1,295 次。虽然 PaddedMat6×8 单独贡献 <5%（因为 UR10 工作集仅 912 bytes，天然适合 L1 缓存），但结合 FP32 数据宽度减半后 Bank 冲突累计降低 63%。

#### ❌ 不好的方面（CUDA 改进的局限）

1. **Strict 阈值（5mm/1°）下收敛率不足**：CUDA-Mixed 在 Strict 阈值下成功率仅 59–64%，而 cuRobo 保持 100%。这是因为 FP32 Jacobian 的精度（相对误差 ~4.2%）在更严格阈值下暴露，混合精度在极高精度要求场景下有局限性。

2. **大批量下吞吐仅可比，不占优**：$N≥4000$ 时 CUDA-Mixed（~157k t/s）与 cuRobo-Graph（145k–163k t/s）吞吐可比。$N=5000$ 时 cuRobo-Graph 更是达到 1,056k t/s（是 CUDA-Mixed 的 6.7 倍）——虽然该性能受批量振荡影响不可推广（$N=4000$ 时 cuRobo-Graph 退化 7.3 倍），但说明在最优条件下 cuRobo 的粒子优化+L-BFGS 方法可以显著超越 DLS 迭代方法。

3. **误差 margin 较紧**：CUDA-Mixed 在 Medium 阈值下的 p95 位置误差为 9.2 mm（阈值 10 mm），margin 仅 0.8 mm。cuRobo-Graph 的亚微米级精度源于其粒子优化方法的固有特性。

4. **与 cuRobo 的加速比被严重高估**：原论文声称 "36.1×"（N=100 时 vs cuRobo-NoGraph）。在公平对比（cuRobo-Graph 开启）下，N=100 的实际加速比为 **2.1×**（80,757 vs 38,398 t/s）。原论文的 "36.1×" 是在 cuRobo 关闭 CUDA Graph 的条件下测得的，计时口径也不一致（CUDA kernel-only vs cuRobo host wall-clock）。

5. **方法适用范围有限**：本文方法仅对比了 UR10 单 seed（zero_seed）、关闭碰撞检测的简化场景。实际应用中需考虑多 seed 全局搜索、碰撞检测、7 自由度冗余机械臂等扩展，当前方法的直接适用性有限。

6. **混合精度对 ε 的敏感性未经全面验证**：Jacobian 精度验证虽表明 ε=1e-6 在 FP32 下可接受，但不同 ε 值（尤其是 ε=1e-5，中位误差 1.9×10⁻³）可能提供更好的精度-性能平衡。当前固定 ε=1e-6 的配置未经过调优。

## 四、对 CUDA 改进的总体评价

**本文的 CUDA 小矩阵加速方案在低至中等批量规模（$N≤1000$）下具有明确的结构性优势：** 单 kernel 全迭代封装从根本上消除了多 kernel 调度和跨 kernel 同步开销，这一优势在 $N=100$ 时体现为相对 cuRobo-Graph 的 2.1 倍吞吐提升。

**但该方案并非全面优于 cuRobo：** 在大批量（$N≥4000$）下吞吐仅可比，在 Strict 阈值下收敛率（59–64%）低于 cuRobo（100%），且方法当前仅覆盖单 seed、无碰撞的简化场景。

**核心工程贡献清晰：** 1 block/target 映射、单 kernel 封装、寄存器 LDLᵀ、PaddedMat6×8、FP32/FP64 混合精度五项设计构成了一个可复现、可扩展的批量 IK GPU 加速基线。该基线的最大价值在于批量扩展的确定性和可预测性——用户无需对不同 $N$ 值进行预扫描或参数调优，吞吐可事先精确计算。

**建议论文定位为：** "面向低至中等批量规模 UR10 IK 的 CUDA 底层小矩阵加速方法"，而非 "通用 GPU IK 替代方案"。结论应明确收缩至调度开销降低和扩展稳定性，避免推广至完整运动规划场景。
