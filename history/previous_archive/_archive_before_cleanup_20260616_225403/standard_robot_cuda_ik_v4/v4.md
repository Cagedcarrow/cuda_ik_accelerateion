# CUDA IK V4 改进方案：从 Multi-Seed IK 升级到约束感知 GPU 运动生成前端

## 0. V4 总定位

V1/V2/V3 的主线是：

```text
V1：CUDA 小矩阵 DLS
V2：解析 Jacobian + DLS
V3：解析 Jacobian + LM + Multi-Seed / Sobol Seed Bank
```

V4 不应继续只堆 IK 求解器，而应升级为：

```text
V4：约束感知 GPU IK / 局部运动生成前端
```

核心变化：

| 阶段    | 主要问题                  | 目标                  |
| ----- | --------------------- | ------------------- |
| V1/V2 | IK 算得慢，Jacobian 不准    | 提速、消除数值差分误差         |
| V3    | Strict SR 受 seed 覆盖影响 | Multi-seed、Sobol、LM |
| V4    | IK 解是否能用于真实运动         | 加入关节连续性、碰撞约束、轨迹平滑   |
| V5    | 真实机器人任务验证             | 抓取/避障/动态重规划         |

---

# 1. V4 的核心目标

## 1.1 技术目标

构建一个 GPU 原生约束感知 IK / 运动生成框架，使其具备以下能力：

1. 批量目标 IK 求解；
2. 多 seed 并行搜索；
3. 关节限位约束；
4. 奇异性 / 可操作性约束；
5. 与上一帧关节角连续；
6. 简化环境碰撞检测；
7. 简化轨迹平滑；
8. 与 cuRobo 做更接近真实机器人场景的对比。

---

## 1.2 与 cuRobo 的竞争定位

V4 仍然不要写成“全面替代 cuRobo”。

更合理的目标是：

> 在简化碰撞和局部轨迹连续任务中，提出一个结构透明、延迟稳定、可解释的 GPU 原生 IK/局部运动生成方案，并与 cuRobo 形成明确边界对比。

V4 可以争取的优势：

| 指标       | V4 目标              |
| -------- | ------------------ |
| 小批量延迟    | 接近或低于 cuRobo-Graph |
| 中等批量有效吞吐 | 接近 cuRobo          |
| 轨迹连续性    | 明显优于纯 IK           |
| 碰撞安全性    | 支持基础碰撞过滤           |
| 实现透明度    | 高于 cuRobo          |
| 可预测性     | GPU 时间随 N 线性或近线性   |

# 3. V4 总体架构

## 3.1 V4 Pipeline

```text
Target Pose Batch
        ↓
Seed Bank Generator / Loader
        ↓
GPU Multi-Seed LM Solver
        ↓
Constraint Residual Builder
        ↓
Collision / Continuity / Joint-Limit Penalty
        ↓
Best Seed Selection
        ↓
Trajectory Consistency Filter
        ↓
Collision-Free Candidate Output
```

---

## 3.2 V4 优化目标函数

V3 只优化位姿误差：

```text
min ||e_pose(q)||²
```

V4 优化扩展为：

```text
min  w_p ||e_pos(q)||²
   + w_R ||e_rot(q)||²
   + w_l ||e_limit(q)||²
   + w_c ||e_collision(q)||²
   + w_s ||q - q_prev||²
   + w_m ||e_manip(q)||²
```

其中：

| 项           | 含义            |
| ----------- | ------------- |
| e_pos       | 位置误差          |
| e_rot       | 姿态误差          |
| e_limit     | 关节限位惩罚        |
| e_collision | 碰撞惩罚          |
| e_smooth    | 与上一帧关节角的连续性约束 |
| e_manip     | 奇异性 / 可操作性惩罚  |

## 4.2 Module B：关节限位 Barrier

### 目标

避免解贴近关节极限或被 clamp 破坏连续性。

### 当前 V3 问题

V3 多数情况下使用：

```text
q = clamp(q, q_min, q_max)
```

问题：

1. clamp 会造成非光滑；
2. 优化器不知道即将撞限位；
3. 可能导致局部收敛异常。

### V4 改进

加入关节限位 barrier loss：

```text
e_limit_i =
    max(0, q_i - q_max_i + margin)
  + max(0, q_min_i + margin - q_i)
```

或使用平滑 barrier：

```text
L_limit = Σ 1 / (q_i - q_min_i + ε)²
        + Σ 1 / (q_max_i - q_i + ε)²
```

### 建议参数

```text
margin = 5° 或 0.087 rad
w_limit = 0.1, 1.0, 10.0 扫描
```

### 验收指标

| 指标                    |         目标 |
| --------------------- | ---------: |
| joint limit violation |          0 |
| near-limit ratio      |         下降 |
| Strict SR             | 不下降超过 2 pp |
| pos_p95_all           |      不显著变差 |

---

## 4.3 Module C：轨迹连续性约束

### 目标

让连续目标的 IK 解在关节空间连续，避免跳解。

### 使用场景

轨迹点：

```text
T_0, T_1, ..., T_M
```

V3 是逐点独立求解，可能出现：

```text
q_0, q_1, ..., q_M
```

其中相邻 q 存在跳变。

### V4 增加 smoothness loss

```text
L_smooth = ||q_t - q_{t-1}||²
```

更进一步：

```text
L_vel = ||q_t - q_{t-1}||²
L_acc = ||q_t - 2q_{t-1} + q_{t-2}||²
```

### 先做局部连续版本

V4 初期只加：

```text
q_prev warm start + smoothness penalty
```

暂不做全轨迹联合优化。

### 验收指标

| 指标                             |            目标 |
| ------------------------------ | ------------: |
| max Δq between adjacent points |            降低 |
| mean Δq                        |            降低 |
| IK SR                          |         不明显下降 |
| path jerk                      |            降低 |
| latency                        | 不超过 V3 的 1.5× |

---

## 4.4 Module D：简化碰撞检测模型

### 目标

让 IK 解不仅满足位姿，还能避开简单障碍物。

### 碰撞模型选择

不要一开始做复杂 mesh collision。先做 sphere model。

#### 机器人模型

将 UR10 每个 link 近似为若干 collision spheres：

```text
link_1: sphere_1, sphere_2
link_2: sphere_3, sphere_4, sphere_5
...
```

每个 sphere 有：

```text
center_local
radius
link_id
```

#### 环境模型

先支持：

1. sphere obstacle；
2. box obstacle；
3. plane obstacle；
4. 后续再支持 SDF grid。

### Sphere-obstacle distance

对球障碍物：

```text
d = ||p_link_sphere - p_obs|| - r_link - r_obs
```

碰撞惩罚：

```text
e_collision = max(0, margin - d)
```

### Box obstacle

先用 AABB 最近点距离：

```text
p_closest = clamp(p, box_min, box_max)
d = ||p - p_closest|| - r_link
```

### 碰撞梯度

对 link sphere 中心 p(q)，碰撞误差对 q 的导数：

```text
∂d/∂q = nᵀ J_p(q)
```

其中：

```text
n = (p - p_obs) / ||p - p_obs||
J_p(q) = sphere center 的位置 Jacobian
```

这可以利用 V2/V3 已有解析 Jacobian 框架。

### 验收指标

| 指标                     |       目标 |
| ---------------------- | -------: |
| collision violation    |       下降 |
| min clearance          |       增大 |
| IK success             |    不下降过多 |
| collision-free success | ≥ 80% 初期 |
| GPU overhead           |       可控 |

---

## 4.5 Module E：奇异性 / 可操作性惩罚

### 目标

避免求解落在奇异附近，提升后续轨迹可执行性。

### 可操作性指标

Yoshikawa manipulability：

```text
m(q) = sqrt(det(J Jᵀ))
```

惩罚：

```text
L_manip = max(0, m_threshold - m(q))²
```

### 简化替代

由于 det 计算和导数复杂，V4 初期可以使用：

```text
condition penalty:
L_cond = 1 / (σ_min(J) + ε)
```

或更简单：

```text
if det(JJᵀ) < threshold:
    increase λ
```

### 初期实现建议

先不加入 loss，只做 diagnostics：

```text
record det(JJᵀ)
record condition number
record singularity warning
```

如果发现失败样本集中在低 manipulability，再加入惩罚项。

---

## 4.6 Module F：Best Candidate Selection

### 当前 V3 选择策略

通常是：

```text
choose min pose loss
```

### V4 选择策略

改为多目标评分：

```text
score =
    w_pose * pose_loss
  + w_col  * collision_loss
  + w_lim  * limit_loss
  + w_smo  * smoothness_loss
  + w_man  * singularity_loss
```

### 选择规则

优先级：

1. 满足 collision-free；
2. 满足 Strict / Medium；
3. 关节变化最小；
4. 距离 limit 远；
5. manipulability 高。

### 推荐 score

```text
score = pose_loss
      + 10.0 * collision_loss
      + 1.0  * limit_loss
      + 0.1  * smooth_loss
```

参数需要扫描。

# 10. 风险控制

## 风险 1：碰撞约束导致 SR 大幅下降

处理：

* 先只做 collision filtering；
* 再做 collision penalty；
* 不要一开始强行同时优化 pose 和 collision。

## 风险 2：GPU kernel 过复杂导致寄存器爆炸

处理：

* 分 kernel：

  * IK kernel；
  * collision evaluation kernel；
  * candidate selection kernel。
* 不要所有逻辑塞进单 kernel。

## 风险 3：与 cuRobo 差距仍然大

处理：

* 明确 V4 是轻量级 constraint-aware IK，不是完整 MotionGen；
* 强调低延迟、透明性、可预测性；
* 不宣传全面替代。

## 风险 4：考研时间被吞

处理：

* V4 作为长期路线；
* 先完成 M0/M1/M2；
* 碰撞和 CUDA 化可放后续。

# 12. 最终判断

V4 的本质不是“再把 IK 快一点”，而是：

> 将 V3 的 GPU multi-seed IK 升级为具备约束意识的局部运动生成器。

如果 V4 成功，论文层级会从：

```text
批量 IK 加速
```

升级为：

```text
GPU 原生约束感知 IK / 局部运动生成方法
```

这会明显比 V1/V2/V3 更接近 cuRobo 的真实应用范围。
