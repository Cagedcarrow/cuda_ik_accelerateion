## 总体判断

新版本**明显比上一版成熟**。上一轮最严重的硬伤——**A4/A5 的 N=100 数据混用**——已经修掉：主表现在把 `cuda (A4 FP64)` 和 `cuda (A5 FP64)` 分开列出，A5 的 N=100 吞吐也改为 52,064 targets/s，对应加速比 18.3×，这已经自洽。

但现在仍有几个**会被审稿人抓住的问题**。主要不是工作量，而是**消融编号、配置定义、表格格式、因果解释边界**。

# 2. 仍然必须修的问题

## 2.1 最大问题：消融编号体系仍然自相矛盾

这是当前版本最严重的问题。

你在 5.3 里先说：

> 结构性设计项（所有消融级别默认启用）：
> 常量内存参数广播
> PaddedMat6x8 共享内存布局

但下面的消融表又写：

| 级别 | ConstMem | PaddedMat |
| -- | -------- | --------- |
| A0 | —        | —         |
| A1 | Yes      | —         |
| A2 | Yes      | Yes       |

这就矛盾了。

如果 ConstMem 和 PaddedMat 是“所有消融级别默认启用”的结构性设计项，那 A0/A1/A2 就不应该关闭它们。
如果 A0/A1/A2 确实在测试 ConstMem/PaddedMat，那么它们就不是“所有消融级别默认启用”的结构性设计项，而是**可量化消融项**。

### 修法

把结构性设计项改成：

> **结构性设计项**：1 block/target、128 threads/block、四 warp 分工、寄存器内 6×6 LDLT、单 kernel DLS 迭代。
> **可量化消融项**：ConstMem、PaddedMat6x8、自适应阻尼、步长钳位、分支对齐、混合精度、CUDA Graph。

不要把 ConstMem 和 PaddedMat 同时写进“结构性设计项”和“消融开关”。

---

## 2.2 A3/A4 的脚注仍然混乱

你现在的脚注写：

> A3 和 A4 的 ConstMem/PaddedMat 状态已在 A2 中覆盖，此处标记为“—”表示该项在消融序列中的编号位置已被自适应阻尼占据，不表示关闭。A3 对应 A2 + 自适应阻尼（关闭 ConstMem 和 PaddedMat）……

这里一句话内部就冲突：

* 前半句说 “— 不表示关闭”；
* 后半句又说 “关闭 ConstMem 和 PaddedMat”。

这是审稿人会直接画红线的地方。

### 建议直接删除 A3

你现在实际表格里也没有 A3 数据。最稳的方式是把消融编号简化：

| 级别 | 含义                                                |
| -- | ------------------------------------------------- |
| A0 | baseline FP64，无 ConstMem，无 PaddedMat，固定 λ         |
| A1 | A0 + ConstMem                                     |
| A2 | A1 + PaddedMat                                    |
| A4 | A2 + fixed λ 对照配置，或者直接改名为 A4-fixed                |
| A5 | A2 + adaptive damping                             |
| A6 | A5 + step clamp + branch align                    |
| A7 | A5 + mixed precision，关闭 step clamp / branch align |
| A8 | A7 + CUDA Graph                                   |

但更干净的是：

| 新编号 | 配置                          |
| --- | --------------------------- |
| B0  | FP64 baseline               |
| B1  | + ConstMem                  |
| B2  | + PaddedMat                 |
| B3  | + Adaptive Damping          |
| B4  | + Step Clamp / Branch Align |
| B5  | Mixed Precision             |
| B6  | CUDA Graph                  |

不要为了保留 A0-A8 而牺牲逻辑清晰性。

## 2.3 A7 配置定义与结论冲突

配置表里写：

| A7 | Step Clamp | Branch Align |
| -- | ---------- | ------------ |
| A7 | Yes        | Yes          |

但后文又写：

> 最优配置为 A7（混合精度 + 自适应阻尼，关闭步长钳位与分支对齐）

这两处冲突。

如果 A7 是最优配置，并且你确实认为 step clamp / branch align 应关闭，那么 A7 表里必须写：

| A7 | ConstMem | PaddedMat | Adaptive Damping | Step Clamp | Branch Align | Precision |
| -- | -------- | --------- | ---------------- | ---------- | ------------ | --------- |
| A7 | Yes      | Yes       | Yes              | —          | —            | FP32+FP64 |

然后 A8 是：

| A8 | Yes | Yes | Yes | — | — | FP32+FP64+Graph |

现在 A7 表格必须改。

## 2.4 “A7 在所有批量上最佳”不严格

你写：

> 最优配置为 A7……在所有批量上取得最佳吞吐

但 N=100 表中：

| Level | Throughput |
| ----- | ---------: |
| A7    |    107,250 |
| A8    |    111,238 |

A8 比 A7 高。所以“所有批量上 A7 最佳”不成立。

### 修法

改成：

> 若不考虑 CUDA Graph replay 带来的轻微测量差异，A7 是主求解器配置中吞吐最高且结构最稳定的配置；A8 在 N=100 上略高，但差异较小，主要反映 launch/replay 机制变化，不改变核心 kernel 设计结论。

或者直接说：

> 主配置采用 A7；A8 仅用于验证 CUDA Graph 对当前 kernel 的边际收益。

# 3. 需要降级的因果判断

## 3.1 “cuRobo 优势主要来自 FP32，而非算法框架效率”太强

你在 7.4 写：

> 这说明 cuRobo 在超大批量上的优势主要来自 FP32 的高吞吐，而非算法框架本身的并行效率。

这个判断过强。因为你自己已经承认：

* cuRobo 是 FP32；
* 多 seed / 多 particle；
* L-BFGS + particle；
* PyTorch / GPU batch 搜索；
* 本文是单 seed DLS；
* 不是等计算量、等精度、等结构比较。

所以你不能严格推出“cuRobo 优势不是算法框架效率”。你只能说：

> 该结果提示，在本文测试口径下，精度配置和底层实现对大批量吞吐具有显著影响；cuRobo 在 FP64-only 对照下表现出的优势，不能简单归因于算法框架本身，也受到 FP32 计算路径和多 particle 并行组织方式的共同影响。

这才严谨。

---

## 3.2 “FP32 到 FP64 类型转换未引入额外 pipeline 停顿”证据不足

你写：

> FP32 到 FP64 的类型转换未引入额外的 pipeline 停顿。

除非 Nsight Compute 里你确实查了 conversion instruction、stall reason、dependency stall，否则这句话太硬。

建议改成：

> 从当前 NCU 指标看，混合精度引入的类型转换没有表现为主导瓶颈；主要瓶颈仍为计算吞吐与寄存器压力。

---

## 3.3 用 N=100 的 NCU 去解释 N=5000 的性能，需要加边界

你多处用 N=100 的 NCU profiling 解释 A7 的整体加速，这可以，但要加一句：

> 当前 NCU profiling 以 N=100 为代表样例，主要用于解释 kernel 内部瓶颈结构；N=5000 下的 SM 填充、wave 数和调度行为仍需进一步 profiling 验证。

否则审稿人会问：你 N=5000 的 1.25×优势，为什么用 N=100 的 profiling 证明？

# 4. mean/std/CI 仍然不够

你现在写：

> 30 次测量的吞吐变异系数约为 2-3%，1.25 倍的优势在测量噪声范围之外。完整的标准差和 95% 置信区间数据见实验数据记录。

这比上一版好，但还不够。因为如果“完整标准差和 95% CI”不在正文、不在附录、不在补充材料，审稿人看不到。

### 建议至少给关键表补一列

主表建议改成：

|  N | Solver | Repeat | GPU time mean ± std ms | Throughput mean ± std targets/s | ConvRate |
| -: | ------ | -----: | ---------------------: | ------------------------------: | -------: |

尤其 N=5000 的 A7 vs cuRobo 必须给：

* A7 mean ± std；
* cuRobo mean ± std；
* 95% CI；
* p 值可选，不强求。

1.25×不是特别大的优势，必须用方差稳住。
