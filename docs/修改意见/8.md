下面给出一个**可直接执行的三档阈值实验方案**。核心目标是把论文从“单一阈值 benchmark”升级为“不同精度等级下的性能边界分析”。

你当前论文的收敛判据本来就是位置误差和姿态误差同时满足才算收敛，只是旧版阈值仍写成 (0.03m / 30^\circ)。 现在应改为三档阈值，并在实验设计里明确三档任务定位。

---

# 一、三档阈值定义

正式采用这三组：

| 等级     |  位置阈值 | 姿态阈值 |              弧度值 | 定位            |
| ------ | ----: | ---: | ---------------: | ------------- |
| Loose  | 30 mm |  10° | 0.1745329252 rad | 宽松任务 / 候选生成   |
| Medium | 10 mm |   5° | 0.0872664626 rad | 普通主 benchmark |
| Strict |  5 mm |   1° | 0.0174532925 rad | 严格阈值压力验证      |

对应代码参数：

```python
THRESHOLD_GROUPS = {
    "loose":  {"pos_tol": 0.030, "rot_tol": 0.1745329252},  # 30 mm / 10 deg
    "medium": {"pos_tol": 0.010, "rot_tol": 0.0872664626},  # 10 mm / 5 deg
    "strict": {"pos_tol": 0.005, "rot_tol": 0.0174532925},  # 5 mm / 1 deg
}
```

---

# 二、论文主线建议

## 主 benchmark 用 Medium

建议主论文默认阈值定为：

[
\boxed{\varepsilon_p=0.01m,\quad \varepsilon_R=0.0873rad\approx5^\circ}
]

原因：

* 比原来的 (30mm/30^\circ) 严格很多；
* 比 (30mm/2^\circ) 更协调，因为位置也收紧了；
* 不会像 (5mm/1^\circ) 那样一开始就过度苛刻；
* 适合作为“普通批量 IK benchmark”。

## Strict 作为压力验证

[
\boxed{\varepsilon_p=0.005m,\quad \varepsilon_R=1^\circ}
]

不要一开始直接把 Strict 当主线。先跑数据。如果 Strict 也稳定，再考虑升级为主线；否则它作为“严格阈值下性能边界”就足够。

---

# 三、实验矩阵

## 3.1 必跑求解器

只需要先跑两个：

| Solver        | 是否必须 | 目的    |
| ------------- | ---- | ----- |
| CUDA B5 mixed | 必须   | 本文主方法 |
| cuRobo        | 必须   | 主对比方法 |

暂时不要全量重跑 B0-B6。
原因：三档阈值 × 七组消融 × 四个 N 会非常大，而且不一定必要。

---

## 3.2 必跑 N 值

保持论文原始规模：

[
N \in {100,\ 500,\ 1000,\ 5000}
]

也就是：

| 阈值组            | N=100 | N=500 | N=1000 | N=5000 |
| -------------- | ----: | ----: | -----: | -----: |
| Loose 30mm/10° |     跑 |     跑 |      跑 |      跑 |
| Medium 10mm/5° |     跑 |     跑 |      跑 |      跑 |
| Strict 5mm/1°  |     跑 |     跑 |      跑 |      跑 |

每组对 CUDA B5 和 cuRobo 都跑。

总实验数：

[
3 \times 4 \times 2 = 24
]

如果 repeat=30，就是 24 组正式结果。这个规模合理。

---

# 四、执行顺序

## 第一步：快速预跑

先不要 repeat=30，先 repeat=5 或 repeat=10。

目的：看 Strict 会不会崩。

优先跑：

| 阈值     |           N | Solver  |
| ------ | ----------: | ------- |
| Medium | 1000 / 5000 | CUDA B5 |
| Strict | 1000 / 5000 | CUDA B5 |

如果 Strict 在 N=1000 / 5000 下收敛率已经低于 0.95，就没必要立刻全量跑 Strict 的 cuRobo，先检查参数和失败分布。

---

## 第二步：正式全量实验

确认没有明显崩溃后，跑完整矩阵：

```text
threshold_group = loose, medium, strict
N = 100, 500, 1000, 5000
solver = cuda_b5, curobo
repeat = 30
seed = zero_seed
target_asset = 原同一批目标
robot = official UR10
tcp = tool0
```

必须保持这些不变：

* UR10 模型不变；
* `tool0` 不变；
* target asset 不变；
* zero_seed 不变；
* repeat=30 不变；
* 时间口径不变；
* CUDA 和 cuRobo 使用同一位置/姿态阈值。

你的论文已经强调统一模型、`tool0`、目标资产、初始种子和误差阈值来构建 benchmark，这个原则不能破坏。

# 八、判定规则

跑完后按这个规则决定论文主阈值。

## 情况 A：Strict 很稳

如果 Strict 满足：

| 指标             |             门槛 |
| -------------- | -------------: |
| CUDA ConvRate  |         ≥ 0.98 |
| CUDA TP        | ≥ Medium 的 70% |
| N=5000 speedup |         ≥ 0.9× |
| Avg Iters      |     没有接近最大迭代次数 |

那么可以把主 benchmark 升级为：

[
\boxed{5mm/1^\circ}
]

这会让论文更强。

---

## 情况 B：Medium 很稳，Strict 有下降

这是最可能也最稳的情况。

主 benchmark 使用：

[
\boxed{10mm/5^\circ}
]

Strict 作为补充实验写：

> 在 (5mm/1^\circ) 严格阈值下，单 seed DLS 的收敛率和吞吐出现一定下降，说明严格精度条件下需要多 seed 或二阶段 refinement，但本文方法仍保持可观吞吐。

---

## 情况 C：Medium 也明显下降

如果 Medium 都不稳，说明位置阈值从 30mm 收到 10mm 后压力较大。此时主 benchmark 用：

[
\boxed{30mm/10^\circ}
]

但这会弱一些。只有在数据很差时才这么退。
