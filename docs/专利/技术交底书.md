# 技术交底书

## 一、发明名称

一种面向标准机械臂批量逆运动学的CUDA并行映射与寄存器级小矩阵求解方法

## 二、技术领域

本发明属于机器人运动学与GPU并行计算交叉领域，具体涉及一种基于CUDA架构的标准机械臂批量逆运动学（Inverse Kinematics, IK）并行加速求解方法。该方法针对6自由度（如Universal Robots UR10）及7自由度（如Franka Panda）串联机械臂的大批量独立目标位姿逆运动学查询任务，通过CUDA Block/Warp/Lane三级并行映射、寄存器级小矩阵LDLᵀ分解求解、PaddedMat6x8共享内存布局优化和FP32/FP64混合精度计算路径设计，在单次GPU kernel launch中完成全部目标的阻尼最小二乘（Damped Least Squares, DLS）迭代求解，显著提升了批量IK的吞吐量、数值稳定性和性能可预测性。

## 三、背景技术

### 3.1 机械臂逆运动学求解的技术背景

逆运动学（IK）是机器人学中的基础计算原语——给定末端执行器的目标位姿（位置和姿态），求解使末端达到该位姿的关节角配置。IK广泛应用于机器人离线采样、抓取候选生成、运动规划初始化、标定辅助和轨迹生成等任务，是机器人操作流程中最频繁调用的计算模块之一。

对于6自由度全旋转关节串联机械臂，其关节变量为 q = [q₁, q₂, q₃, q₄, q₅, q₆]ᵀ ∈ R⁶。末端执行器在基座坐标系下的位姿由齐次变换矩阵 T_EE(q) ∈ SE(3) 表示，该矩阵通过6个关节变换矩阵的链式乘积得到。IK问题即：给定目标位姿 Tᵈ ∈ SE(3)，求解 q* 使得 T_EE(q*) = Tᵈ 在给定容差内成立。

### 3.2 现有IK求解方法及其局限性

#### 3.2.1 阻尼最小二乘法（DLS）与Levenberg-Marquardt变体

DLS是机械臂IK中最常用的迭代数值方法之一。其核心思想是将非线性IK问题在每次迭代中线性化为6×6正规方程，并通过阻尼项保证数值稳定性。LM方法在DLS基础上引入自适应阻尼调度——误差下降时减小阻尼（趋向Gauss-Newton步），误差上升时增大阻尼（趋向梯度下降步）。

DLS/LM的优势在于问题形式清楚、可直接实现、每步计算代价可分析。但其根本局限在于：当目标数量增至数百或数千时，CPU端的逐目标串行迭代导致总耗时线性增长。对于N=5000的批量IK查询，即使在单目标平均仅需1ms收敛的情况下，串行处理的总耗时也超过5秒，无法满足交互式或近实时应用的需求。

#### 3.2.2 GPU加速机器人求解器（cuRobo / PyRoki）

cuRobo（NVIDIA Research）是目前最具代表性的GPU加速机器人运动生成系统。其核心策略是：为每个IK目标生成多个粒子（particles，默认约200个），每个粒子从不同初始种子出发，通过L-BFGS优化器并行求解，最后从多个解中选取最优者。cuRobo在较大批量（N>1000）下，通过多粒子并行有效填充GPU计算单元，实现了高SM利用率。

PyRoki（UC Berkeley）基于JAX框架实现GPU加速的运动学优化工具链，强调模块化、可组合性和研究灵活性，支持多种优化器和运动学约束的即插即用。

两类系统的共同特征是：GPU IK的性能不仅取决于数学算法本身，还取决于框架层级、kernel launch次数、批处理策略和精度路径。但它们在小至中批量（N=100-1000）场景下的per-target固定开销较高——cuRobo的多粒子搜索（每目标200粒子×多seed）在小批量下，每目标搜索开销占总耗时比例较高（实测N=100时Python/C++软件栈固定开销占总耗时90%以上），未能随batch size减小而等比降低。此外，基于PyTorch等高层框架的GPU求解器在特定批量规模下可能因GPU内存管理机制（如CUDA Caching Allocator的碎片化/重分配）触发求解时间的非线性退化——实测中cuRobo在N=4000、7000、9000、10000四个批量规模上出现约230ms的退化模式（约为正常32ms的7倍），且该退化与N值无单调关系，呈现"正常→退化→恢复→再退化"的批量振荡。

#### 3.2.3 小矩阵线性系统的GPU求解挑战

对于6自由度机械臂，每次DLS迭代需求解的线性系统 H·Δq = g 的规模仅为6×6。通用线性代数库（如cuBLAS）的Warp级分块策略针对n≥32的矩阵优化，其最小优化规模远大于6×6。对6×6极小矩阵而言，每次GEMM/TRSM调用需独立kernel launch，其启动和调度开销（通常为5-10μs量级）可能远超实际分解计算量（6×6 LDLᵀ仅需约86次标量运算，约0.1μs即可完成）。此外，6×6矩阵在cuBLAS中无法利用Tensor Core或高效的Warp级tiling策略。

因此，6×6小矩阵的GPU高效求解不能直接依赖通用线性代数库，而需要专门设计的寄存器级轻量实现。

#### 3.2.4 收敛阈值对算法评估的决定性影响

在批量IK求解器的性能评估中，收敛阈值的选择直接影响优化项的性能归因。实验表明，在宽松阈值（位置30mm/姿态10°）下，固定阻尼系数λ（无自适应策略）的DLS基线配置在N=100时吞吐达134k targets/s、收敛率1.000、平均迭代仅4.3次——表现与自适应阻尼配置接近，甚至因无分支开销而更快。然而当阈值收紧至工程合理水平（位置10mm/姿态5°）后，同一固定λ配置的收敛率骤降至0.522-0.830，平均迭代次数激增至31-80次，吞吐暴跌至7.6k-12.5k targets/s。这揭示了一个方法论问题：过于宽松的阈值会系统性地低估收敛策略的价值，甚至产生"自适应阻尼带来负收益"的伪象。

#### 3.2.5 现有技术的综合不足

综合以上分析，现有技术在面向标准机械臂批量IK的GPU加速方面存在以下五方面不足：

（1）**小矩阵库调用开销过大**：6×6线性系统的通用库求解存在不可接受的kernel launch与计算量之比；

（2）**小批量场景效率低下**：现有GPU求解器的per-target固定开销（多粒子、多kernel launch）在N<1000时导致GPU计算单元利用率不足；

（3）**迭代控制流映射困难**：DLS的自适应阻尼、收敛判定、步长控制和分支对齐等串行逻辑难以自然映射到GPU的SIMT（单指令多线程）执行模型；

（4）**精度配置不灵活**：纯FP64实现无法充分利用消费级GPU（如Ada Lovelace架构）的高FP32:FP64吞吐比（64:1），而全FP32实现又可能损害收敛稳定性；

（5）**批量扩展确定性不足**：基于高层框架的GPU求解器的性能在特定批量规模下不可预测——退化模式不由用户可控参数（如N值大小）决定，而由GPU内存管理器的内部状态决定，对需要稳定延迟的机器人控制回路构成实质性风险。

## 四、发明内容

### 4.1 本发明要解决的技术问题

针对上述现有技术的不足，本发明要解决的技术问题是：

**问题一（并行映射问题）**：如何将批量IK的DLS迭代过程——包括FK、数值Jacobian、阻尼正规矩阵构造、LDLᵀ求解和关节更新——高效映射到CUDA的Block/Warp/Lane三级并行层次，使得N个独立目标的全部迭代在单次kernel launch中完成，消除per-target和per-iteration的launch累积开销。

**问题二（小矩阵求解问题）**：如何在GPU上以最低开销求解每次DLS迭代中的6×6对称正定线性系统，避免通用线性代数库的kernel launch和全局内存访问开销。

**问题三（内存布局问题）**：如何消除共享内存中6×6矩阵列访问导致的Bank冲突——该冲突在H=Jᵀ·W²·J构造阶段将共享内存有效吞吐降低至理论峰值的约1/3。

**问题四（精度效率平衡问题）**：如何在消费级GPU上平衡FP32的高吞吐与FP64的高精度，使批量IK求解在维持99.8%以上收敛率的同时，吞吐量提升120-149%。

**问题五（批量扩展确定性问题）**：如何使批量IK求解器在任意批量规模下的性能行为完全可预测——GPU时间与N严格线性、吞吐恒定，消除因GPU内存管理机制或框架开销导致的非线性退化。

### 4.2 技术方案

本发明提出一种面向标准机械臂批量逆运动学的CUDA并行映射与寄存器级小矩阵求解方法，包括以下四项核心技术方案。

#### 4.2.1 发明点一：Block级批量并行映射与Warp级任务分工方法

**核心思想**：将每个IK目标映射为1个CUDA block（含128个线程=4个Warp×32个Lane），block内按Warp分工协作完成DLS迭代的全部计算步骤，全部DLS迭代循环（最大K_max=160次迭代）在单次kernel launch中完成，所有N个目标并行求解。

**（a）Grid到Block的映射**

设批量规模为N（目标位姿数量），目标位姿矩阵为 T_tgt⁽ᵇ⁾ ∈ SE(3)（b = 0, 1, ..., N-1），关节角种子为 q⁽ᵇ·⁰⁾ ∈ R⁶。Grid维度定义为：

Grid = (N, 1, 1)

即每个目标位姿分配一个CUDA block，各block之间完全独立——无需跨block通信，无需全局同步。Block索引b = blockIdx.x直接标识目标ID。

**（b）Block内部128线程4-Warp分工**

每个Block固定为128线程（4 Warps × 32 Lanes/Warp）。该配置通过约束驱动的排除法从三种候选方案中选出：

- **候选方案A（每线程一任务，Fine-grained）**：每个线程独立处理一个完整目标。寄存器需求估算约372个/线程（J: 64 + H: 64 + 6段FK中间4×4矩阵: 192 + 误差/梯度/步长: 36 = 372个32位寄存器），远超硬件上限（255个/线程），导致local memory spilling，吞吐急剧下降。排除。

- **候选方案B（每Block一任务，Cooperative）**：1 block/target，block内线程协作。寄存器需求约94-98个/线程，共享内存需求约1,616字节/block。Nsight Compute实测：94寄存器/线程（B4 FP64），98寄存器/线程（B5混合精度），1.616 KB共享内存/block，无local memory spill。采用。

- **候选方案C（每Warp一任务）**：1 warp/target，32线程/warp。Warp内线程数不足以并行展开Jacobian 6列（需6路数据并行的FK计算），且4个warp/block可恰好对应4项主要任务类别。仅当DOF≥12且J矩阵规模超过warp容量时考虑。排除。

最终映射方案为128线程/Block（4 Warps），Warp级任务分工如下表所示：

| Warp | Lane范围 | 计算任务 | 数学映射 | 并行粒度 | 执行模式 |
|:----:|:--------:|---------|---------|:--------:|:--------:|
| W0 | 0--31 | FK链式乘法、位姿误差计算、LDLᵀ求解、LM阻尼更新、收敛判定 | 全部DLS控制流 | 串行控制 | Lane 0串行执行 |
| W1 | 32--63 | 数值雅可比矩阵6列并行组装 | J的第j列由Lane 32+j负责，每列2次FK扰动计算 | 6路数据并行 | 数据并行 |
| W2 | 64--95 | 阻尼正规矩阵H与梯度g构造 | Lane 64+(i×6+j)负责H_{ij}元素的内积计算 | 36路数据并行 | 数据并行 |
| W3 | 96--127 | 关节角步长更新、限位投影 | 6路数据并行 | 6路数据并行 | 数据并行 |

**（c）Warp内线程任务的数学映射**

**Warp 0（Lane 0-31，控制流）**：Lane 0执行全部控制流逻辑，其余31个Lane处于等待状态。Warp 0执行的主要操作包括：

- 前向运动学（FK）：根据当前关节角q计算末端位姿T(q)，读取 `__constant__` 内存中的运动学参数（c_segment_origins[96]、c_segment_axes[18]、c_q_index[6]、c_T_wrist3_to_tcp[16]），调用Rodrigues旋转公式和4×4齐次矩阵乘法链式计算。单次FK运算量约为~450次乘加+12次三角函数（6次Rodrigues + 5次4×4矩阵乘法 + 1次工具变换）。

- 位姿误差计算：位置误差 e_p = pᵈ - p(q) ∈ R³；姿态误差采用李代数形式 e_R = Log(Rᵈ·R(q)ᵀ)∨ ∈ R³；总误差 e = [e_p; e_R] ∈ R⁶。

- LDLᵀ求解：将共享内存中的H矩阵（PaddedMat6x8布局）拷贝至寄存器中的6×6密集数组，调用寄存器级ldlt_solve_6x6()函数完成分解和前代/回代求解。

- LM阻尼更新：根据收敛状态（误差改进/退化/停滞）调整阻尼参数λ。

- 收敛判定：采用三档递进阈值体系——Loose (ε_p=0.03 m, ε_R=0.1745 rad, 30mm/10°)、Medium (ε_p=0.01 m, ε_R=0.0873 rad, 10mm/5°, 主 benchmark) 和 Strict (ε_p=0.005 m, ε_R=0.0175 rad, 5mm/1°)——位置误差与姿态误差独立判定，两者同时满足各自阈值方标记为收敛。

**Warp 1（Lane 32-63，6路数据并行）**：Lane 32+j（j=0,...,5）负责计算Jacobian的第j列。采用中心差分法：

J_{:,j} = [e(q+ε·e_j) - e(q-ε·e_j)] / (2ε)

其中ε = 1×10⁻⁶为扰动步长，e_j为单位向量。每列需2次FK扰动计算——每个Lane独立执行：
1. 从共享内存拷贝当前q至本地寄存器
2. 对第j个关节施加正/负扰动：q_plus[j] += ε, q_minus[j] -= ε
3. 分别调用forward_kinematics()计算T_plus和T_minus
4. 计算位姿误差e_plus和e_minus
5. 中心差分：J_{:,j} = (e_plus - e_minus) / (2ε)

12次FK计算（6列×2次扰动）被压缩为约2次FK延迟，因为6个Lane的FK计算在SM内并行执行。

**Warp 2（Lane 64-95，36路数据并行）**：Lane 64+(i×6+j)（i,j=0,...,5）负责计算H_{ij}元素。每个Lane执行一个6项加权内积：

H_{ij} = Σ_{k=0}^{5} w_k² · J_{ki} · J_{kj}

其中w_k为权重矩阵W的对角元素。对角线元素加阻尼：H_{ii} += λ²。Lane还负责计算梯度向量的对应分量：g_i = Σ_{k=0}^{5} w_k² · J_{ki} · e_k。

该阶段的关键特征是：36个Lane同时从共享内存读取Jacobian矩阵的列——若无PaddedMat6x8布局优化，stride=6的自然行主序布局将导致2-3路Bank冲突（详见发明点三）。

**Warp 3（Lane 96-127，6路数据并行）**：Lane 96+i（i=0,...,5）负责第i个关节的步长更新和限位投影：

- 关节限位投影：q_i⁽ᵏ⁺¹⁾ = clamp(q_i⁽ᵏ⁾ + Δq_i, q_{i,min}, q_{i,max})
- 步长由‖Δq‖_∞ ≤ 0.25 rad的硬约束确定：若‖Δq‖_∞ ≤ 0.25则α=1.0（全步长）；否则α=0.25/‖Δq‖_∞（等比缩放）

**（d）单次Kernel Launch完成全部DLS迭代**

区别于现有GPU求解器（如cuRobo）的多次kernel launch策略（per-target或per-iteration），本发明将整个DLS迭代循环（最大K_max=160次迭代）封装在单个kernel内部。N个block各自独立运行至多K_max次迭代，无需CPU端的中途干预和重新launch。单kernel架构的关键优势包括：

1. **消除kernel launch累积开销**：cuRobo等框架型求解器的跨语言调用栈（Python→C++→CUDA→C++→Python）在N=100时固定开销占总耗时90%以上。
2. **迭代增量成本线性可控**：每增加一轮迭代的边际成本仅约0.02 ms（N=5000条件下），不存在host-device同步的放大效应。
3. **GPU时间与N严格线性**：实测R² > 0.999——N翻倍意味着block数翻倍，在SM数量固定的条件下GPU时间精确翻倍，吞吐保持恒定。
4. **完全确定性的性能行为**：不存在动态内存分配、无跨block通信、无GPU-CPU同步——吞吐在任何N值下均可从事先的计算精确预测。

#### 4.2.2 发明点二：寄存器驻留的6×6 LDLᵀ分解求解器

**核心思想**：利用6×6矩阵规模固定且足够小的特性，将完整的LDLᵀ分解和三角求解过程全部置于GPU寄存器中执行，消除通用线性代数库的kernel launch开销、全局内存往返和共享内存访问。

**（a）LDLᵀ分解的数学形式**

对于6×6对称正定矩阵H = Jᵀ·W²·J + λ²I，LDLᵀ分解（无需选主元）将H分解为：

H = L · D · Lᵀ

其中L为单位下三角矩阵（L_{ii}=1），D为对角矩阵。该分解的选择基于以下考虑：
- 与Cholesky分解（H = L·Lᵀ）相比，LDLᵀ避免了6次平方根运算——GPU上平方根指令的吞吐量约为FMA（融合乘加）的1/4至1/8。
- λ²I正则项保证H的对称正定性，因此无需选主元（无需行交换），分解过程数值稳定。

**（b）LDLᵀ分解算法（寄存器内实现）**

算法步骤（所有中间变量均为寄存器内标量或小数组）：

**阶段一：LDLᵀ分解**

```
for j = 0 to 5:
    // 对角元更新
    D[j] = A[j][j]
    for k = 0 to j-1:
        D[j] -= L[j][k] * L[j][k] * D[k]
    
    L[j][j] = 1.0
    
    // 非对角元更新
    for i = j+1 to 5:
        L[i][j] = A[i][j]
        for k = 0 to j-1:
            L[i][j] -= L[i][k] * L[j][k] * D[k]
        L[i][j] /= D[j]
```

**阶段二：前代求解（L·y = g）**

```
for i = 0 to 5:
    y[i] = g[i]
    for k = 0 to i-1:
        y[i] -= L[i][k] * y[k]
```

**阶段三：对角缩放（D·z = y）**

```
for i = 0 to 5:
    y[i] /= D[i]
```

**阶段四：回代求解（Lᵀ·Δq = z）**

```
for i = 5 down to 0:
    dq[i] = y[i]
    for j = i+1 to 5:
        dq[i] -= L[j][i] * dq[j]
```

**（c）运算量统计**

| 阶段 | 循环范围 | 标量运算次数 | 可FMA映射 |
|------|---------|:----------:|:---------:|
| 对角元更新 | j=0..5, k=0..j-1 | 15 | 15 |
| 非对角元更新 | j=0..5, i=j+1..5, k=0..j-1 | 20 | 20 |
| L缩放（除D_j） | j=0..5, i=j+1..5 | 15 | 0（除法） |
| 前代求解 | i=0..5, k=0..i-1 | 15 | 15 |
| 对角缩放 | i=0..5 | 6 | 0（除法） |
| 回代求解 | i=5..0, j=i+1..5 | 15 | 15 |
| **合计** | | **86** | **65** |

总计86次标量运算中，65次为乘加/乘减运算（可映射为单周期FMA指令），21次为除法（由SFU特殊功能单元流水线执行）。总耗时约0.1μs，完全在寄存器中完成，零内存流量。每轮迭代时间在1.945-1.951 μs内波动（<0.3%）——无论阻尼因子λ如何变化，LDLᵀ的计算路径和操作数均不变，不存在LM线搜索的步长回退风险。

**（d）寄存器驻留分析**

LDLᵀ求解阶段涉及的完整数据集包括：
- H矩阵（36个FP64元素）+ L矩阵（36个FP64元素）+ D对角元（6个FP64元素）+ 中间向量y, z, dq（18个FP64元素）= 96个FP64元素 = 768字节 = 约192个32位寄存器的等效存储空间。

在Ada Lovelace架构（255寄存器/线程上限，128线程/block）下，上述数据集完全可驻留在单个Lane的寄存器文件中，无需local memory spilling（Nsight Compute实测确认：local memory spill = 0）。

**（e）编译时优化**

矩阵维度6为编译时常量（constexpr），三重循环的迭代次数（j=0..5, k=0..j-1, i=j+1..5）完全确定。通过NVCC的 `#pragma unroll` 指令，编译器将全部循环展开为直线代码序列：
- 消除分支预测失败（无条件跳转）
- 消除循环控制开销（索引递增和条件检查）
- 编译器可进一步应用指令级并行优化（ILP），将无数据依赖的标量运算调度至同一指令发射周期

**（f）与通用库方案的技术效果对比**

对比通用线性代数库（cuBLAS GEMM/TRSM）：通用库求解极小矩阵时，kernel launch与全局内存往返等开销远超实际分解计算量（86次标量运算 vs 5-10μs launch开销）；本发明寄存器LDLᵀ求解阶段本身不产生全局内存流量——这对DRAM带宽受限的批量IK场景具有关键意义。

**（g）FP64精度的数值稳定性作用**

FP64提供15位有效数字，即使在Jacobian条件数达10⁶时仍能保证分解精度。DLS求解器在14-16轮迭代后的自然收敛精度（Strict阈值下PosErr均值1.8 mm, RotErr均值远低于1°）已大幅超越最严格的阈值要求——收敛不是因为"恰好满足阈值"，而是因为求解器本身的精度上限足够高。这一属性是本发明三档阈值鲁棒性的核心结构基础之一。

#### 4.2.3 发明点三：PaddedMat6x8共享内存布局的Bank冲突消除方法

**核心思想**：将共享内存中6×6矩阵的行步长从自然值6扩展为8（添加2列零填充），通过改变Bank访问模式消除stride=6布局导致的系统性Bank冲突。

**（a）Bank冲突的成因分析**

CUDA共享内存由32个Bank组成，每个Bank宽度为4字节。连续的4字节字映射到连续的Bank（字地址w映射到Bank w mod 32）。当同一Warp内的多个线程同时访问同一Bank的不同地址时，发生Bank冲突——访问被串行化，有效带宽降低。

在6×6矩阵的自然行主序布局（stride=6 doubles = 48 bytes = 12 banks per row）中：
- 地址映射：addr(r,c) = r×12 + c×2（每个double占2个4字节字）
- Bank映射：B(r,c) = (r×12 + c×2) mod 32

在H=Jᵀ·W²·J构造阶段（Warp 2的36线程并行），线程(i,j)需读取Jacobian的第i行和第j行进行列内积计算。以读取J的第c列为例，6个元素访问的Bank序列为：

{2c, 12+2c, 24+2c, 36+2c≡4+2c, 48+2c≡16+2c, 60+2c≡28+2c} (mod 32)

由于gcd(12, 32)=4，Bank访问模式以32/4=8为周期重复。在6行访问中，不可避免地发生Bank索引的模冲突，导致2-3路Bank冲突。Nsight Compute实测确认该冲突模式：共享内存吞吐量仅为理论峰值的约1/3。

**（b）PaddedMat6x8布局方案**

将6×6矩阵的行步长扩展至8个double（即6×8布局），添加2列零填充。地址映射变为：

addr(r,c) = r×16 + c×2

Bank映射：B'(r,c) = (r×16 + c×2) mod 32

关键性质：由于gcd(16, 32)=16，Bank访问模式以32/16=2为周期。

- **偶数行**（r = 0, 2, 4）：起始Bank索引为c×2（Bank 0-15范围）
- **奇数行**（r = 1, 3, 5）：起始Bank索引为16+c×2（Bank 16-31范围）

两组使用的Bank集合完全不重叠。在LDLᵀ分解和阻尼正规矩阵构造等核心计算中——这些操作每次仅涉及≤2行的同时访问——因此可消除stride=6布局导致的主要系统性Bank冲突。

**（c）PaddedMat6x8的C++零开销封装**

```cpp
struct PaddedMat6x8 {
    double* data;  // 指向 __shared__ double[6×PADDEDMAT_STRIDE]

    __device__ __forceinline__ double& operator()(int row, int col) {
        return data[row * PADDEDMAT_STRIDE + col];
    }
    __device__ __forceinline__ const double& operator()(int row, int col) const {
        return data[row * PADDEDMAT_STRIDE + col];
    }
};
```

其中PADDEDMAT_STRIDE为编译时常量（消融级别≥B2时为8，否则为6）。`__device__ __forceinline__` 确保编译后为单条索引计算指令，NVCC -O2（sm_89）编译后PTX指令序列与裸指针访问一致——无额外抽象性能开销。

**（d）存储开销分析**

额外存储 = 6行 × (8-6)列 × 8 bytes/double = 96 bytes/矩阵。对于Jacobian和Hessian两个矩阵，总额外存储 = 192 bytes，占SM共享内存总量（100 KB）的约0.19%。该代价可忽略不计。

**（e）实测验证**

Nsight Compute实测数据确认：
- B4配置（FP64 + PaddedMat6x8）：shared bank conflicts = 3,522次
- B5配置（PaddedMat6x8 + FP32数据宽度）：shared bank conflicts = 1,295次，较B4减少49%。

B5的bank conflict进一步降低源于FP32数据宽度为FP64的一半（4 bytes vs 8 bytes），对共享内存的自然对齐访问减少了两路和三路bank冲突的发生频率。但即使以B4的峰值3,522次冲突计，其占总共享访问波前的比例不足2%，bank conflict的减少是混合精度加速的伴随现象而非主因。

#### 4.2.4 发明点四：FP32/FP64混合精度计算路径

**核心思想**：将批量IK的DLS计算管线按精度敏感度划分为FP32段和FP64段——FK、Jacobian、H和g构造等计算密集型操作在FP32下执行以获得高吞吐（利用Ada Lovelace架构64:1的FP32:FP64吞吐比）；LDLᵀ求解、阻尼更新和收敛判定等数值敏感操作保留FP64以保证解的质量。

**（a）精度敏感度分析**

完整DLS迭代管线包含两类不同精度敏感度的运算：

（a）**低精度敏感度运算**：FK链式乘法（Rodrigues旋转公式+4×4矩阵乘法）、位姿误差计算（向量减法+旋转矩阵乘法）和数值Jacobian组装（中心差分+线性近似）。这些运算涉及大量三角函数和矩阵乘法，其精度需求为：Jacobian扰动步长ε=1×10⁻⁶在FP32下引入的相对舍入误差约为1×10⁻⁷量级，远小于迭代收敛容差（1×10⁻²量级），因此FP32精度损失可忽略。

（b）**高精度敏感度运算**：LDLᵀ线性系统求解涉及条件数敏感的除法运算（L_{ij} = .../D_j）和累积求和（前代/回代中的ΣL_{ik}·y_k）。H和g的元素累加涉及36个内积，每个内积为6项加权乘积之和。FP32累加的截断误差传播可能影响搜索方向的质量，因此这些运算需FP64精度。

**（b）混合精度数据流设计**

```
FP32计算段（高吞吐，~90%计算量）:
  ├── 前向运动学(FK): forward_kinematics_f(s_q, s_T)
  │     └── 运算量: 6次Rodrigues + 5次4×4矩阵乘法
  ├── 位姿误差计算: pose_error_f(s_T, s_T_tgt, s_err)
  │     └── 位置误差: 向量减法; 姿态误差: 旋转矩阵乘法+反对称分解
  └── 数值雅可比组装: J的6列中心差分计算（Warp 1, 6路并行）
        └── 每列2次FP32 FK扰动计算

  ┌── FP32 → FP64 类型转换边界 ──┐
  │  (Hessian和gradient以FP64累积) │

FP64累积段（高精度）:
  ├── H矩阵构造: H_{ij} = Σ_k w_k²·J_{ki}·J_{kj}  (FP64累加)
  ├── g向量构造: g_i = Σ_k w_k²·J_{ki}·e_k  (FP64累加)
  └── H_{ii} += λ² (FP64阻尼项)

  ┌── FP64 LDLᵀ求解（高精度关键路径）──┐

FP64求解段:
  ├── LDLᵀ分解: 寄存器内FP64运算
  ├── 前代+对角缩放+回代求解: 全部FP64
  ├── LM阻尼更新: λ *= 0.7 or 2.0 (FP64)
  └── 收敛判定: ‖e_p‖₂和θ_R与阈值比较 (FP64)

  ┌── FP64 → FP32 类型转换边界 ──┐
  │  (关节步长Δq以FP32写回)        │

FP32写回段:
  └── 关节更新+限位投影: FP32
```

**（c）类型转换点实现**

在LDLᵀ求解入口处，将FP32共享内存中的Hessian矩阵和梯度向量显式转换为FP64寄存器数组：

```cpp
double H_dense[36], g_dense[6];
for (int r = 0; r < 6; r++) {
    for (int c = 0; c < 6; c++) {
        H_dense[r*6 + c] = (double)H(r, c);  // FP32 → FP64
    }
    g_dense[r] = (double)s_g[r];              // FP32 → FP64
}
ldlt_solve_6x6(H_dense, g_dense, s_dq);       // FP64 LDLᵀ核心
```

LDLᵀ求解完成后，将FP64结果Δq以FP32精度写回共享内存用于后续的关节更新。

**（d）精度验证**

混合精度B5配置的收敛率实测结果：N=100为1.000（100%），N=500为0.998（99.8%），N=5000为0.9998（99.98%），N=10000为0.9996（99.96%）。所有批量下收敛率均不低于99.8%，未因主体精度的降低而产生可测量的收敛退化。这验证了FP32/FP64精度边界划分的正确性——LDLᵀ求解器、阻尼调节和收敛判定保留FP64精度路径足以保证整体求解质量。

从Nsight Compute指标看，混合精度引入的类型转换（FP32→FP64于LDLᵀ求解入口，FP64→FP32于结果回写）没有表现为主导瓶颈；B5主要瓶颈仍为计算吞吐（60.73%）与寄存器压力（98寄存器/线程）。

### 6.2 运动学模型建立

#### 6.2.1 UR10正运动学模型

UR10为6自由度全旋转关节串联机械臂，其关节构型由6维关节角向量描述：

**q = [q₁, q₂, q₃, q₄, q₅, q₆]ᵀ ∈ R⁶**

其中q_i为第i个旋转关节的角位移（单位：rad），受限于URDF中声明的关节限位 [q_{i,min}, q_{i,max}]。

末端执行器（tool0）在基座坐标系下的位姿由齐次变换矩阵 **T_EE(q) ∈ SE(3)** 表示：

**T_EE(q) = [R(q)  p(q); 0ᵀ  1]**

其中R(q)∈SO(3)为3×3旋转矩阵，p(q)∈R³为位置向量。

正运动学由6个关节变换矩阵与末端工具变换的链式乘积给出：

**T_EE(q) = Π_{i=1}⁶ (T_i⁰ · R(a_i, q_i)) · T_tool**

其中T_i⁰∈SE(3)为第i个关节的固定原点变换（由URDF中joint origin的xyz/rpy确定），a_i∈R³为关节旋转轴单位向量（‖a_i‖=1），R(a_i, q_i)为绕轴a_i旋转q_i的Rodrigues旋转矩阵，T_tool为wrist_3坐标系至tool0的固定工具变换。

**Rodrigues旋转公式**（GPU实现为 `build_rotation_matrix()`）：

**R(a, q) = I + sin(q)·[a]_× + (1-cos(q))·[a]_×²**

其中[a]_×为向量a的反对称矩阵。在GPU上，sin/cos由SFU（特殊功能单元）流水线执行，与算术运算并行。

#### 6.2.2 位姿误差定义

给定目标位姿 Tᵈ = [Rᵈ  pᵈ; 0ᵀ 1]，当前位置T(q) = [R(q)  p(q); 0ᵀ 1]。

**位置误差**：e_p = pᵈ - p(q) ∈ R³

**姿态误差**：采用李代数形式，
e_R = Log(Rᵈ · R(q)ᵀ)∨ ∈ R³
其中Log为SO(3)上的对数映射，∨为反对称矩阵到向量的逆映射。

总六维误差向量：**e(q) = [e_p; e_R] ∈ R⁶**

**收敛判据**：采用三档递进阈值体系——Loose (ε_p=0.03 m / 30 mm, ε_R=0.1745 rad / 10°)、Medium (ε_p=0.01 m / 10 mm, ε_R=0.0873 rad / 5°, 主 benchmark) 和 Strict (ε_p=0.005 m / 5 mm, ε_R=0.0175 rad / 1°)。位置与姿态误差具有不同物理量纲，因此采用独立阈值进行收敛判定，避免单一加权误差掩盖某一项未收敛的情况。

#### 6.2.3 DLS正规方程

第k次迭代中，关节增量Δq由如下加权最小二乘问题确定：

**Δq = argmin_{Δq} ‖W(J·Δq - e)‖₂² + λ²‖Δq‖₂²**

其中J∈R^{6×6}为位姿误差对关节变量的Jacobian，W为位置与姿态误差权重矩阵（6×6对角正定），λ>0为阻尼系数。

上述优化问题对应的法方程为：

**(Jᵀ·W²·J + λ²I)·Δq = Jᵀ·W²·e**

令阻尼正规矩阵 **H = Jᵀ·W²·J + λ²I ∈ R^{6×6}**（Gauss-Newton近似海森），梯度向量 **g = Jᵀ·W²·e ∈ R⁶**，则每次DLS迭代归结为固定规模线性系统 **H·Δq = g**。

**数值Jacobian计算**（中心差分法）：

**J_{:,j} = [e(q+ε·e_j) - e(q-ε·e_j)] / (2ε)**，其中ε = 1×10⁻⁶，e_j为单位向量。

**关节更新与限位投影**：

**q⁽ᵏ⁺¹⁾ = Π_Q(q⁽ᵏ⁾ + α·Δq)**

其中α∈(0,1]为步长因子，Π_Q为关节限位投影算子：Π_Q(q_i) = clamp(q_i, q_{i,min}, q_{i,max})。

步长α由‖Δq‖_∞ ≤ 0.25 rad的硬约束确定——若‖Δq‖_∞ ≤ 0.25则α=1.0（全步长）；否则α=0.25/‖Δq‖_∞（等比缩放）。

#### 6.3.4 DLS迭代主循环的伪代码

以下为每个Block内部执行的DLS迭代主循环（K_max=160次迭代）：

```
// Phase 1: 初始化
从全局内存加载目标位姿 → s_T_tgt
从全局内存加载初始种子 → s_q, s_q_ref, s_q_best
s_lambda ← λ_base (2e-4)
s_stagnation ← 0
s_best_pos_err ← INFINITY

// Phase 2: DLS迭代循环
for iter = 0 to max_iter-1:

    // 2a. 前向运动学 (Warp 0, Lane 0)
    if lane_id == 0:
        forward_kinematics(s_q, s_T)  // 读取 __constant__ 内存
        __syncwarp()

    // 2b. 位姿误差计算 (Warp 0, Lane 0)
    if lane_id == 0:
        s_err = pose_error(s_T, s_T_tgt)
        s_pos_err = ||s_err[0:3]||₂
        rot_geodesic = rotation_geodesic_distance(s_T, s_T_tgt)
        __syncwarp()

    // 2c. 收敛判定 (Warp 0, Lane 0)
    if lane_id == 0:
        if s_pos_err <= pos_tol AND rot_geodesic <= orient_tol:
            s_converged = 1
            break
        if s_pos_err < s_best_pos_err:
            s_best_pos_err = s_pos_err
            s_q_best = s_q
            s_stagnation = 0
        else:
            s_stagnation += 1
    __syncthreads()
    if s_converged: break

    // 2d. 数值Jacobian (Warp 1, 6路数据并行)
    if lane_id >= 32 AND lane_id < 38:  // Lanes 32-37
        j = lane_id - 32
        q_plus = s_q; q_plus[j] += ε
        forward_kinematics(q_plus, T_plus)
        q_minus = s_q; q_minus[j] -= ε
        forward_kinematics(q_minus, T_minus)
        J(0:2, j) = (T_plus.pos - T_minus.pos) / (2ε)
        J(3:5, j) = rotation_column_diff(T_plus, T_minus) / (2ε)
    __syncthreads()

    // 2e. 自适应阻尼 (Warp 0, Lane 0)
    if lane_id == 0:
        if iter == 0:
            // 距离初始化
            if s_pos_err > 0.1:
                s_lambda = max(λ_base, λ_far * s_pos_err / λ_scale)
            else:
                s_lambda = λ_floor + λ_base * s_pos_err / λ_scale
        else:
            // Marquardt误差驱动更新
            if s_pos_err < s_prev_pos_err:
                s_lambda *= 0.7  // 改进→减小阻尼→趋向Gauss-Newton
            else:
                s_lambda *= 2.0  // 退化→增大阻尼→趋向梯度下降
        s_lambda = clamp(s_lambda, 1e-4, 0.5)
        // 停滞超驰
        if s_stagnation > 12:
            s_lambda = min(s_lambda * 5.0, 0.5)
    __syncthreads()

    // 2f. 阻尼正规矩阵H构造 (Warp 2, 36路数据并行)
    if lane_id >= 64 AND lane_id < 100:  // Lanes 64-99
        row = (lane_id - 64) / 6
        col = (lane_id - 64) % 6
        sum = 0.0
        for k = 0 to 5:
            w_k = c_weight_schedule[k]
            sum += J(k, row) * w_k * w_k * J(k, col)
        if row == col: sum += s_lambda
        H(row, col) = sum
    __syncthreads()

    // 2g. 梯度向量g构造 (Warp 3的部分Lane, 6路数据并行)
    if lane_id >= 96 AND lane_id < 102:  // Lanes 96-101
        i = lane_id - 96
        sum = 0.0
        for k = 0 to 5:
            w_k = c_weight_schedule[k]
            sum += J(k, i) * w_k * w_k * s_err[k]
        s_g[i] = sum
    __syncthreads()

    // 2h. LDLᵀ求解 (Warp 0, Lane 0)
    if lane_id == 0:
        copy H(PaddedMat6x8) → H_dense[36] (寄存器)
        copy s_g[6] → g_dense[6] (寄存器)
        ldlt_solve_6x6(H_dense, g_dense, s_dq)  // 86次标量运算，全寄存器
    __syncthreads()

    // 2i. 关节更新与限位投影 (Warp 3, 6路数据并行)
    if lane_id >= 96 AND lane_id < 102:
        i = lane_id - 96
        dq_infnorm = max(|s_dq[0]|, ..., |s_dq[5]|)
        if dq_infnorm < 1e-8:
            s_converged = 1  // 停滞收敛
            break
        if dq_infnorm > 0.25:
            scale = 0.25 / dq_infnorm
            s_dq[i] *= scale
        q_new = s_q[i] + s_dq[i]
        s_q[i] = clamp(q_new, c_joint_limits[2*i], c_joint_limits[2*i+1])
    __syncthreads()
    s_prev_pos_err = s_pos_err

// Phase 3: 写回结果
if lane_id == 0:
    d_results[blockIdx.x * 6 : (blockIdx.x+1) * 6] = s_q (或 best_s_q)
    d_errors[blockIdx.x * 2] = s_best_pos_err
    d_errors[blockIdx.x * 2 + 1] = rotation_geodesic
    d_iterations[blockIdx.x] = s_iter_count
```

#### 6.3.5 自适应阻尼策略的实现

自适应阻尼策略（B3及以上消融级别启用）实现了LM混合阻尼调度，包含三层逻辑：

**层一：距离初始化（迭代0）**

```
if pos_err > 0.1:
    λ = max(λ_base, λ_far × pos_err / λ_scale)
    λ = min(λ, λ_far × 3.0)
else:
    λ = λ_floor + λ_base × pos_err / λ_scale
```

**层二：Marquardt误差驱动更新（迭代1+）**

```
if pos_err < prev_pos_err:  λ *= 0.7   // 改进
else:                        λ *= 2.0   // 退化
λ = clamp(λ, 1e-4, 0.5)
```

**层三：停滞超驰**

```
if stagnation > 12:
    λ = min(λ × 5.0, 0.5)
```

其中λ_base=2e-4, λ_far=5e-2, λ_floor=1e-4, λ_scale=8e-2，存储于 `__constant__` 内存c_lambda_params[4]中。

该策略的关键特征是：分段线性、距离比例初始化、误差驱动更新——相对于完整LM的平方根/指数运算，额外计算开销极小（仅含if-else、乘法、fmin/fmax），适合GPU SIMT执行模型。实测效果：将收敛率从43-83%（固定λ，Medium阈值）恢复至99.8-100%，迭代次数减少59-83%。

### 6.4 LDLᵀ寄存器求解器的具体实现

#### 6.4.1 函数接口

```cuda
__device__ __forceinline__ void ldlt_solve_6x6(
    const double* H,    // [in]  6×6对称正定矩阵（行主序，36个元素）
    const double* g,    // [in]  6维梯度向量
    double* dq);        // [out] 6维解向量Δq
```

`__device__ __forceinline__` 双重属性确保编译器将该函数内联至调用点，所有局部变量分配在寄存器中。

#### 6.4.2 完整算法实现

**步骤1：拷贝输入至局部数组**

```
double A[6][6];  // 寄存器内6×6矩阵
for (i = 0..5, j = 0..5):
    A[i][j] = H[i*6 + j]
```

**步骤2：LDLᵀ分解**

```
double L[6][6] = {0};  // 单位下三角矩阵（寄存器）
double D[6];            // 对角矩阵（寄存器）

for j = 0 to 5:
    // 对角元: D[j] = A[j][j] - Σ_{k<j} L[j][k]²·D[k]
    D[j] = A[j][j]
    for k = 0 to j-1:
        D[j] -= L[j][k] * L[j][k] * D[k]

    L[j][j] = 1.0

    // 非对角元: L[i][j] = (A[i][j] - Σ_{k<j} L[i][k]·L[j][k]·D[k]) / D[j]
    for i = j+1 to 5:
        L[i][j] = A[i][j]
        for k = 0 to j-1:
            L[i][j] -= L[i][k] * L[j][k] * D[k]
        L[i][j] /= D[j]
```

**步骤3：前代求解 L·y = g**

```
double y[6];
for i = 0 to 5:
    y[i] = g[i]
    for k = 0 to i-1:
        y[i] -= L[i][k] * y[k]
```

**步骤4：对角缩放 D·z = y**

```
for i = 0 to 5:
    y[i] /= D[i]
```

**步骤5：回代求解 Lᵀ·Δq = z**

```
for i = 5 downto 0:
    dq[i] = y[i]
    for j = i+1 to 5:
        dq[i] -= L[j][i] * dq[j]
```

所有循环在编译时完全展开——三重嵌套的迭代次数（j=0..5, k=0..j-1, i=j+1..5）为编译时常量，NVCC `#pragma unroll` 将其展开为约86条标量运算的直线代码序列。该求解器的三个核心属性——FP64精度（15位有效数字）、固定成本（每轮~0.1μs，波动<0.3%）和零内存流量——共同构成了本发明三档阈值鲁棒性的结构基础。

### 6.5 PaddedMat6x8的具体实现

#### 6.5.1 C++封装代码

```cuda
struct PaddedMat6x8 {
    double* data;

    __device__ __forceinline__ PaddedMat6x8(double* d) : data(d) {}

    __device__ __forceinline__ double& operator()(int row, int col) {
        return data[row * PADDEDMAT_STRIDE + col];
    }

    __device__ __forceinline__ const double& operator()(int row, int col) const {
        return data[row * PADDEDMAT_STRIDE + col];
    }
};

// FP32变体（用于混合精度B5）
struct FloatPaddedMat6x8 {
    float* data;

    __device__ __forceinline__ FloatPaddedMat6x8(float* d) : data(d) {}

    __device__ __forceinline__ float& operator()(int row, int col) {
        return data[row * PADDEDMAT_STRIDE + col];
    }
};
```

#### 6.5.2 Bank冲突消除的数学原理

对于stride=8（PADDEDMAT_STRIDE=8）的布局：

每行占8个double = 64 bytes = 16个Bank（每个Bank 4 bytes）。
- 偶数行（r=0,2,4）：Bank起始于c×2 mod 32，使用Bank 0-15
- 奇数行（r=1,3,5）：Bank起始于16+c×2 mod 32，使用Bank 16-31

因为gcd(16,32)=16，偶/奇数行使用的Bank集合完全不重叠。在核心计算中（每次≤2行同时访问），Bank冲突被系统性消除。
