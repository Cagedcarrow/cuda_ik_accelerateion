# 图3：PaddedMat6x8共享内存布局与Bank访问模式对比图 — 绘制描述词

## 一、图的目标与定位

本图对比展示 stride=6（非填充，左侧）与 stride=8（PaddedMat6x8，右侧）两种共享内存布局下的CUDA Bank访问模式，直观说明Bank冲突的成因以及PaddedMat6x8如何通过改变行步长消除系统性Bank冲突。

图类型：**双栏对比图 + Bank映射表**（Comparison Diagram with Bank Mapping Tables）

推荐绘图工具：**TikZ**（LaTeX，适合精确的矩阵和颜色映射）或 **Matplotlib**（Python，适合表格化热力图展示）

## 二、图的结构布局

建议采用**左右双栏对比布局**，中间以箭头分隔（标注"PaddedMat6x8优化"）。

### 2.1 左侧：Stride=6 非填充布局（问题展示）

**标题**："Stride = 6（非填充布局）"

#### 2.1.1 矩阵内存布局表

展示一个6×6的double矩阵在共享内存中的地址映射表。每个单元格显示 (地址, Bank号)。

地址公式：addr(r,c) = r×12 + c×2（每个double占2个4字节字）
Bank公式：B(r,c) = (r×12 + c×2) mod 32

**6×6矩阵布局表（stride=6）**：

| r\c | c=0 | c=1 | c=2 | c=3 | c=4 | c=5 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **r=0** | a0,B0 | a2,B2 | a4,B4 | a6,B6 | a8,B8 | a10,B10 |
| **r=1** | a12,B12 | a14,B14 | a16,B16 | a18,B18 | a20,B20 | a22,B22 |
| **r=2** | a24,B24 | a26,B26 | a28,B28 | a30,B30 | a32,B0 | a34,B2 |
| **r=3** | a36,B4 | a38,B6 | a40,B8 | a42,B10 | a44,B12 | a46,B14 |
| **r=4** | a48,B16 | a50,B18 | a52,B20 | a54,B22 | a56,B24 | a58,B26 |
| **r=5** | a60,B28 | a62,B30 | a64,B0 | a66,B2 | a68,B4 | a70,B6 |

#### 2.1.2 Bank冲突标注

**关键性质**：gcd(12, 32) = 4 → Bank访问模式以 32/4 = 8 为周期重复

**以读取第c=1列为例（6个元素 J[0][1], J[1][1], ..., J[5][1]）**：

| 行r | 地址 | Bank | 与哪个行冲突？ |
|:---:|------|:----:|---------------|
| 0 | a2 | **B2** | ← 与r=2冲突 |
| 1 | a14 | **B14** | ← 与r=3冲突 |
| 2 | a26 | **B26** | 独立 |
| 3 | a38 | **B6** | 独立 |
| 4 | a50 | **B18** | 独立 |
| 5 | a62 | **B30** | 独立 |

**Bank B2冲突详情**：
- J[0][1] 位于 Bank B2 @ 地址a2
- J[2][5] 位于 Bank B2 @ 地址a34（不同地址，同一Bank → 2路Bank冲突）

类似地，B14也存在冲突（J[1][1] @ a14 vs J[3][3] @ a44）。

在H=Jᵀ·W²·J构造阶段，Warp 2的36个线程同时读取Jacobian的6列——每个列访问产生2-3路Bank冲突。

**Bank冲突热力图标注**：
在6×6表格中，用红色高亮标注存在Bank冲突的单元格位置（基于该列6个Bank索引的模冲突分析）。在表格下方标注：

```
Bank冲突次数 (NCU实测, B4配置): 3,522 次
共享内存吞吐量: 约为理论峰值的 1/3
```

#### 2.1.3 Bank环示意图（可选补充）

在小图中展示32个Bank（0-31）的环形布局，用连线标注J[0][1]和J[2][5]都映射到Bank B2（不同地址），形成Bank冲突。

### 2.2 右侧：Stride=8 PaddedMat6x8布局（解决方案）

**标题**："Stride = 8（PaddedMat6x8布局）"

#### 2.2.1 矩阵内存布局表

展示一个6×8的double矩阵在共享内存中的地址映射表。列6和7为零填充列（以灰色底色标识）。

地址公式：addr(r,c) = r×16 + c×2
Bank公式：B'(r,c) = (r×16 + c×2) mod 32

**6×8矩阵布局表（stride=8）**：

| r\c | c=0 | c=1 | c=2 | c=3 | c=4 | c=5 | c=6* | c=7* |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **r=0** | a0,B0 | a2,B2 | a4,B4 | a6,B6 | a8,B8 | a10,B10 | a12,B12 (pad) | a14,B14 (pad) |
| **r=1** | a16,B16 | a18,B18 | a20,B20 | a22,B22 | a24,B24 | a26,B26 | a28,B28 (pad) | a30,B30 (pad) |
| **r=2** | a32,B0 | a34,B2 | a36,B4 | a38,B6 | a40,B8 | a42,B10 | a44,B12 (pad) | a46,B14 (pad) |
| **r=3** | a48,B16 | a50,B18 | a52,B20 | a54,B22 | a56,B24 | a58,B26 | a60,B28 (pad) | a62,B30 (pad) |
| **r=4** | a64,B0 | a66,B2 | a68,B4 | a70,B6 | a72,B8 | a74,B10 | a76,B12 (pad) | a78,B14 (pad) |
| **r=5** | a80,B16 | a82,B18 | a84,B20 | a86,B22 | a88,B24 | a90,B26 | a92,B28 (pad) | a94,B30 (pad) |

\* 标记的列为零填充列（padding columns, 列索引6和7）

#### 2.2.2 Bank分离机制

**关键性质**：gcd(16, 32) = 16 → Bank访问模式以 32/16 = 2 为周期

**Bank集合分离**：
- **偶数行（r=0, 2, 4）**：起始Bank = c×2 mod 32 → **Bank 0-15**
  - r=0: B0,B2,B4,B6,B8,B10
  - r=2: B0,B2,B4,B6,B8,B10
  - r=4: B0,B2,B4,B6,B8,B10
- **奇数行（r=1, 3, 5）**：起始Bank = 16+c×2 mod 32 → **Bank 16-31**
  - r=1: B16,B18,B20,B22,B24,B26
  - r=3: B16,B18,B20,B22,B24,B26
  - r=5: B16,B18,B20,B22,B24,B26

**两组Bank集合完全不重叠！**

在核心计算中（LDLᵀ分解每次涉及≤2行同时访问，H构造每次涉及≤2行读取），Bank冲突被系统性消除。

#### 2.2.3 Bank访问安全标注

在6×8表格下方标注：

```
Bank冲突次数 (NCU实测, B5配置): 1,295 次
减少: 49% (从3,522降至1,295)
额外存储开销: 96 bytes/矩阵 (6行 × 2填充列 × 8 bytes)
             占总SM共享内存 (100KB) 的 <0.2%
```

在6×8表格中：
- 列6和7用灰色底色标注为"零填充列"
- 偶数行用浅蓝色底色，奇数行用浅橙色底色，强化"两组Bank集合分离"的视觉效果

### 2.4 底部：数学原理总结框

跨两栏的底部总结框：

```
┌─────────────────────────────────────────────────────────────┐
│  Bank冲突消除的数学原理                                       │
│                                                             │
│  Bank映射: B(r,c) = (r × K + c × 2) mod 32                  │
│                                                             │
│  条件: 当且仅当 gcd(K, 32) ≥ 4 且 K < 32 时,                │
│         同一列6个元素的Bank索引必然存在模冲突                │
│                                                             │
│  Stride=6 → K=12 → gcd(12,32)=4 → 冲突周期8 → 2-3路冲突    │
│  Stride=8 → K=16 → gcd(16,32)=16 → 周期2 → 偶/奇行Bank分离 │
│                                                             │
│  PaddedMat6x8的本质: 选择stride使 gcd(stride×2, 32) 最大化  │
└─────────────────────────────────────────────────────────────┘
```

## 五、特别注意事项

1. **Bank编号需要清晰可见**——这是读者理解Bank冲突的直接入口
2. **左侧的冲突标注**必须非常直观，建议用红色连线连接冲突的单元格
3. **右侧的偶/奇行颜色分离**是视觉核心，必须一眼看出Bank 0-15和Bank 16-31的分组
4. **零填充列**不要过于突出——它们是"无用的存储代价"，用灰色低调表示即可
5. 右下角的"Bank冲突减少49%"数据需要用大号字体突出显示
6. 如果需要简化，左侧可以只展示一个6×6表格，右侧只展示一个6×8表格（含填充列），但Bank编号和冲突标注不能省略
7. 地址编号（a0, a2, a4...）可以简化或省略，但Bank编号（B0-B31）必须保留
