# 图4：混合精度计算路径数据流图 — 绘制描述词

## 一、图的目标与定位

本图展示本发明B5混合精度配置的完整计算路径，清晰标注FP32段（绿色）→ FP32→FP64转换点（橙色）→ FP64段（蓝色）→ FP64→FP32转换点（橙色）→ FP32写回段（绿色）的精度边界和类型转换位置。这是理解"混合精度在维持99.98%+收敛率的同时实现148-154%吞吐提升"这一核心有益效果的关键图。

图类型：**数据流图 + 精度边界标注**（Data Flow Diagram with Precision Boundaries）

推荐绘图工具：**draw.io**（适合颜色分区的数据流图）或 **TikZ**（LaTeX，适合学术论文风格）

## 二、图的结构布局

建议采用**纵向数据流**布局（从上到下），数据从顶部（输入）流向底部（输出），精度边界以水平虚线标注。

┌────────────────────────────────────────────┐

### 2.2 段一详细展开：FP32 高吞吐段

**背景色**：浅绿色 (#E8F5E9)

**输入数据**（顶部标注）：
- `d_targets[N×16]` — FP32目标位姿矩阵（全局内存）
- `d_seeds[N×6]` — FP64初始种子（全局内存，精度保留）
- `__constant__` 内存参数 — FP64常量（c_segment_origins[96], c_segment_axes[18]等）

**处理步骤**（以圆角矩形表示，从上到下连接）：

| 步骤 | 模块 | Lane分配 | 运算量/次 | 精度敏感度 |
|:----:|------|:--------:|:---------:|:---------:|
| 1 | FK链式乘法 forward_kinematics_f() | W0, Lane 0 | ~450 乘加 + 12 三角函数 | **低** (ε=1e-6时, FP32舍入误差~1e-7, 远小于收敛容差1e-2) |
| 2 | 位姿误差 pose_error_f() | W0, Lane 0 | 向量减法 + 旋转矩阵乘法 + 反对称分解 | **低** |
| 3 | 收敛预判 ‖e_p‖₂ + θ_R | W0, Lane 0 | 范数计算 + 阈值比较 | **低** (阈值0.03m/0.5236rad远大于FP32精度) |
| 4 | Jacobian 6列中心差分 | W1, Lanes 32-37 | 12次FK + 6次差分 | **低** (中心差分O(ε²)主导误差, 非舍入误差) |

**右侧标注框**：

```
┌──────────────────────────────────┐
│ FP32 精度分析                    │
│                                  │
│ 扰动步长: ε = 1×10⁻⁶            │
│ FP32相对舍入误差: ≈ 1×10⁻⁷      │
│ 远小于收敛容差: ≈ 1×10⁻²         │
│                                  │
│ → FP32精度损失可忽略             │
│ → Ada FP32:FP64 吞吐比 ≈ 64:1   │
└──────────────────────────────────┘
```

### 2.3 精度边界1：FP32 → FP64 转换点

**以水平虚线标注，跨越全图宽度，橙色底色 (#FFF3E0)**

标注内容：
```
═══════════════════════════════════════════════
 精度边界 1: FP32 → FP64 转换
═══════════════════════════════════════════════

代码转换:
  for r=0..5, c=0..5:
    H_dense[r*6+c] = (double)H(r,c);  // FP32共享内存 → FP64寄存器
  for r=0..5:
    g_dense[r] = (double)s_g[r];

原因:
  → H和g的累加涉及36个内积, 每个内积6项加权乘积之和
  → FP32累加的截断误差传播可能影响搜索方向质量
  → 因此以FP64精度累积, 但H/g在共享内存中仍为FP32以节省带宽
```

### 2.4 段二详细展开：FP64 累积段

**背景色**：浅蓝色 (#E3F2FD)

| 步骤 | 模块 | Lane分配 | 运算量 | 原因 |
|:----:|------|:--------:|:------:|------|
| 5 | H矩阵FP64累加 | W2, Lanes 64-99 (36路并行) | 36路×6项内积×FP64 FMA | FP64累加防止截断误差传播 |
| 6 | g向量FP64累加 | W3部分, Lanes 96-101 (6路并行) | 6路×6项内积×FP64 FMA | 同上 |
| 7 | H[i][i] += λ² | W2对应Lane | 6次FP64 FMA | λ²为FP64精度, 需同精度累加 |

### 2.5 段三详细展开：FP64 LDLᵀ求解段（关键路径）

**背景色**：深蓝色 (#BBDEFB)，加粗边框表示"关键精度路径"

| 步骤 | 子阶段 | 运算量 | 说明 |
|:----:|--------|:------:|------|
| 8a | LDLᵀ分解: 对角元更新 (15次FP64乘加) | j=0..5, k=0..j-1 | D[j] -= L[j][k]²·D[k] |
| 8b | LDLᵀ分解: 非对角元更新 (20次FP64乘加) | i=j+1..5, k=0..j-1 | L[i][j] -= L[i][k]·L[j][k]·D[k] |
| 8c | LDLᵀ分解: L缩放 (15次FP64除法) | i=j+1..5 | L[i][j] /= D[j] |
| 9 | 前代求解 L·y=g (15次FP64乘减) | i=0..5, k=0..i-1 | y[i] -= L[i][k]·y[k] |
| 10 | 对角缩放 z=y/D (6次FP64除法) | i=0..5 | y[i] /= D[i] |
| 11 | 回代求解 Lᵀ·Δq=z (15次FP64乘减) | i=5..0, j=i+1..5 | dq[i] -= L[j][i]·dq[j] |
| 12 | LM阻尼更新 | W0, Lane 0 | λ*=0.7 or 2.0 (FP64) |
| 13 | 收敛精确判定 | W0, Lane 0 | FP64 ‖e_p‖₂和θ_R与阈值比较 |

**总计**: 86次标量运算（65次可映射为FMA），全部FP64精度，全部寄存器内执行，零全局内存访问

**右侧标注框**：

```
┌──────────────────────────────────┐
│ 为何LDLᵀ保留FP64?               │
│                                  │
│ 1. 条件数敏感的除法运算           │
│    L[i][j] /= D[j]               │
│    → D[j]可能非常小, 除法放大误差 │
│                                  │
│ 2. 累积求和容易误差传播           │
│    Σ L[i][k]·y[k] (前代)          │
│    → FP32截断误差每步放大         │
│                                  │
│ 3. 阻尼更新和收敛判定             │
│    → 直接影响解的质量和终止条件   │
│                                  │
│ 4. 计算量极小(86次运算)           │
│    → FP64额外开销可忽略           │
└──────────────────────────────────┘
```

### 2.6 精度边界2：FP64 → FP32 转换点

**以水平虚线标注，跨越全图宽度，橙色底色 (#FFF3E0)**

标注内容：
```
═══════════════════════════════════════════════
 精度边界 2: FP64 → FP32 转换
═══════════════════════════════════════════════

代码转换:
  for i=0..5:
    dq_f[i] = (float)s_dq[i];  // FP64寄存器 → FP32共享内存

原因:
  → Δq的精度需求: 关节更新步长通常在1e-3到1e-1 rad量级
  → FP32精度(≈7位有效数字)足以表示关节增量
  → 后续关节更新和限位投影无需FP64
```

### 2.7 段四详细展开：FP32 写回段

**背景色**：浅绿色 (#E8F5E9)

| 步骤 | 模块 | Lane分配 | 说明 |
|:----:|------|:--------:|------|
| 14 | Δq FP64→FP32转换 | W0, Lane 0 | 类型转换 |
| 15 | 关节更新 + 限位投影 | W3, Lanes 96-101 (6路并行) | q_i^(k+1) = clamp(q_i^(k) + α·Δq_i, lo, hi) |
| 16 | 步长裁剪 (A6 only) | W0, Lane 0 | ‖Δq‖_∞ > 0.35 → 等比缩放 |
| 17 | 分支对齐 (A6 only) | W0, Lane 0 | atan2归一化 ±2π修正 |
| 18 | 结果写回全局内存 | W0, Lane 0 | d_results[blockIdx.x*6], d_errors, d_iterations (FP32) |

## 四、尺寸建议

- 画布：纵向A4或16:9（约1200×1600像素等效，纵向布局）
- 段一: 25%高度
- 精度边界1: 5%高度
- 段二: 10%高度
- 段三: 30%高度（关键路径，最大面积）
- 精度边界2: 5%高度
- 段四: 15%高度
- 验证结果卡片: 10%高度

## 五、特别注意事项

1. **精度边界线必须粗且醒目**（建议4-5px虚线），这是理解混合精度的关键
2. **段三（FP64 LDLᵀ求解段）必须用最深的蓝色和加粗边框突出**，因为它是"不能损失精度"的关键路径
3. 每个处理步骤旁边用括号标注FP32或FP64类型，字体颜色与所在区段颜色对应
4. 转换点处标注具体的C++代码转换语句（简短形式）
5. 底部验证结果卡片中的数据必须与论文最新数据一致
6. 在段一右侧的FP32精度分析框中，明确写出"FP32舍入误差~1e-7 << 收敛容差~1e-2"这个关键不等式
7. 在段三右侧的"为何保留FP64"框中，条件数敏感的除法是首要原因
8. 可选的补充：在段一和段四右侧分别标注Ada Lovelace的FP32:FP64吞吐比（64:1）作为上下文
