## 1. 论文三大贡献

### 贡献 1：标准 UR10 批量 IK Benchmark 构建

构建了可复现的标准 UR10 批量 IK benchmark，统一模型、tool0、目标位姿资产、初始种子和误差阈值，消除了跨求解器比较中的模型/数据/阈值口径歧义。

**证据：**
- Benchmark 配置：`standard_robot_cuda_ik/config/benchmark.yaml`
- 目标位姿：`standard_robot_cuda_ik/data/targets/` (12 N 值, seed=42)
- 种子数据：`standard_robot_cuda_ik/data/seeds/` (4 策略 × 12 N)
- 阈值定义：`standard_robot_cuda_ik/benchmark/common.py` → Loose/Medium/Strict

### 贡献 2：CUDA 并行映射与寄存器级 6×6 LDLT

提出了 1 block/target, 128 threads/block 的 CUDA 并行映射方案，在单次 kernel launch 中完成全部 DLS 迭代，并通过阶段式 flat threadIdx.x 分工、寄存器级 6×6 LDLᵀ 求解、PaddedMat6x8 共享内存 Bank 冲突降低、混合精度计算路径实现高效批量 IK。

**证据：**
- Kernel 源码：`standard_robot_cuda_ik/src/cuda/cuda_ik_6dof.cu`
- 设备端工具：`standard_robot_cuda_ik/src/cuda/cuda_utilities.cuh`
- 构建系统：`standard_robot_cuda_ik/CMakeLists.txt` (10 消融级别)

### 贡献 3：系统性能证据链

通过 B0-B6 消融、cuRobo 统一口径比较、三档组合阈值扫描、N=100→10000 全量程固定步长扫描（12 个 N 值）、Nsight Compute profiling、Nsight Systems CUDA API trace 和 7DOF Panda 正确性验证，构成覆盖收敛鲁棒性、批量扩展性和架构瓶颈的多维度证据链。

**证据：**
- 消融数据：`data/results/ablation/ablation_medium.csv`
- 全量程数据：`data/results/full_range/full_range_comparison.csv`
- NCU profiling：`data/profiling/ncu_summary.csv`
- Nsight Systems：`experiments/curobo_latency_spike_diagnosis/results/`
- Panda 验证：`data/results/panda_7dof/7dof_verification.csv`

## 6. 计时口径标准

| 口径 | 测量范围 | 工具 | 论文使用 |
|------|---------|------|:---:|
| `kernel_time_only` | GPU kernel 设备端执行时间 | `cudaEventElapsedTime` (kernel begin/end) | **CUDA B5 主数据** |
| `gpu_end_to_end_time` | kernel + H2D/D2H + device sync | `cudaEventElapsedTime` (gpu begin/end) | 辅助参考 |
| `host_api_total_time` | 含主机端预处理和 API 调用 | `std::chrono::steady_clock` | 工程参考 |
| cuRobo host time | Python→C++→CUDA 全调用栈 | `time.perf_counter()` + `torch.cuda.synchronize()` | **cuRobo 主数据** |

> **重要：** CUDA B5 的"测量时间"与 cuRobo 的"测量时间"计时口径不同，不能直接比较"GPU 时间"。加速比应理解为吞吐比值。

## 7. cuRobo 振荡诊断结论

基于 6 阶段诊断实验 + Nsight Systems CUDA API trace：

1. **已排除：** 运行顺序敏感性、进程状态污染、PyTorch CUDA Caching Allocator（cudaMalloc/cudaFree <1% API 时间）
2. **强证据指向：** cuRobo 内部 sub-batch 划分策略在不同 N 值触发不同的 kernel launch 粒度（N=4000: 14,108 kernel vs N=5000: 5,945 kernel, 2.37×）
3. **CUDA B5 对此类问题结构免疫：** 单 kernel 全迭代封装，kernel launch 数恒为 1

**论文推荐表述：**
> 退化更可能来自 cuRobo 内部 sub-batching/tiling/kernel launch granularity 的 batch-size-dependent execution path 解释，而非 PyTorch CUDA Caching Allocator 碎片化。

## 8. Panda 7DOF 的角色定位

- **仅用作：** 正确性验证（FK/IK 数值一致性）、维度参数化代码路径验证
- **不作为：** 正式性能对比、高自由度扩展性证据
- **推荐表述：** "说明该实现框架具有向 7DOF 扩展的工程可行性，但其性能边界仍需进一步系统测试。"
