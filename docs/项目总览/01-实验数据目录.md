## 2. 主实验数据 `standard_robot_cuda_ik/data/`

### 2.1 目标位姿与种子数据

**targets/** — IK 目标位姿（36 files）

```
targets/ur10_seed42_N{100,500,1000,2000,3000,4000,5000,6000,7000,8000,9000,10000}.{bin,csv,json}
```

- 固定随机种子 42 生成，UR10 工作空间内可达位姿
- 格式：binary (.bin) 供 CUDA runner 直接读取；CSV/JSON 供 Python 求解器加载
- 论文使用的 12 个 N 值全覆盖

**seeds/** — 初始关节角种子（96 files）

```
seeds/ur10_seed42_{zero,home,random,near_ground_truth}_seed_N{100..10000}.{bin,json}
```

四种种子策略：

| 策略 | 说明 | 论文使用 |
|------|------|:---:|
| `zero_seed` | 全零初始关节角（运动学最远端） | **主实验默认** |
| `home_seed` | UR10 home configuration | 种子策略对比 |
| `random_seed` | 随机采样 | 未使用 |
| `near_ground_truth_seed` | 接近真解的扰动 | 未使用 |

#### 2.2.2 消融实验 `results/ablation/`

**论文 6.3 节（表 6.3/6.4/6.5）和消融分析的数据来源。**

| 文件 | 内容 | 阈值 |
|------|------|------|
| `ablation_medium.csv` | **权威消融数据** — B0/B3/B5 @ Medium 阈值 | 10mm/5° |
| `ablation_ur10_old_threshold.csv` | B1/B2/B4/B6 边际贡献（旧阈值参考） | 30mm/30° |
| `mixed_precision_ablation.csv` | FP64 vs Mixed (FP32+FP64) 精度对比 | 10mm/5° |

消融级别速查：

| Level | 二进制 | 关键特征 |
|:-----:|:------:|---------|
| B0 | A0 | FP64 基线：global memory, 固定阻尼 |
| B1 | A1 | + 常量内存 |
| B2 | A2 | + PaddedMat6x8（Bank conflict 降低） |
| B3 | A5 | + 自适应阻尼（**收敛率关键驱动**） |
| B4 | A6 | + 步长钳位 + 分支对齐（证明为负收益） |
| B5 | A7 | **混合精度（主配置）**：FP32 FK/Jacobian + FP64 LDLT |
| B6 | A8 | + CUDA Graph replay（边际收益 +3.7%） |

## 3. cuRobo 振荡诊断 `experiments/curobo_latency_spike_diagnosis/results/`

独立排查实验，用于诊断 cuRobo 的批量敏感振荡现象。

### 3.1 诊断实验 CSV

| 文件 | 阶段 | 内容 |
|------|:---:|------|
| `curobo_latency_scan_ordered.csv` | Phase 1 | 顺序扫描 N=100→10000 |
| `curobo_latency_scan_randomized.csv` | Phase 2 | 3 组随机顺序扫描 |
| `curobo_latency_scan_fresh_process.csv` | Phase 3 | 独立子进程隔离 (N=4000/5000/7000/8000) |
| `curobo_latency_fixed_max_batch.csv` | Phase 4 | 固定 max_batch_size=10000 |

### 3.2 Nsight Systems Profiling

| 文件 | 内容 |
|------|------|
| `nsys_N4000.nsys-rep` | N=4000 退化点 CUDA API trace (2.1 MB) |
| `nsys_N5000.nsys-rep` | N=5000 正常点 CUDA API trace (965 KB) |
| `nsys_N4000.sqlite` / `nsys_N5000.sqlite` | SQLite 数据库 |
| `profiler_nsys_N4000.json` / `profiler_nsys_N5000.json` | 解析后的 profiler 摘要 |

**Nsight 关键发现（N=4000 vs N=5000）：**

| 指标 | N=4000 (退化) | N=5000 (正常) | 比值 |
|------|:---:|:---:|:---:|
| CUDA kernel 启动数 | 14,108 | 5,945 | 2.37× |
| cudaEventRecord 调用 | 5,069 | 390 | 13× |
| cudaStreamWaitEvent 调用 | 4,985 | 350 | 14× |
| cudaMalloc/cudaFree 开销 | <1% API 时间 | <1% API 时间 | — |

结论：根因定位于 cuRobo 内部 sub-batch 划分策略的批量依赖性，PyTorch CUDA Caching Allocator 被明确排除。

## 5. 基准测试标准配置（固定不变）

今后所有新增实验必须沿用以下配置，确保与论文数据可比：

```yaml
robot: UR10 (official URDF)
tool: tool0
seed: 42
seed_strategy: zero_seed        # 主实验默认
convergence_threshold:
  default: Medium               # pos=0.010m, rot=0.0873rad (5°)
  loose:   {pos: 0.030, rot: 0.1745}   # 仅参考
  strict:  {pos: 0.005, rot: 0.0175}   # 压力测试
max_iterations: 160
repeat: 30
warmup: 3
weight_level: 2                 # CUDA B5
cuda_graph: false
curobo:
  num_seeds: 1
  seed_solver_num_seeds: 1
  self_collision_check: false
  use_cuda_graph: false
timing:
  cuda:  cudaEventElapsedTime (kernel_only + gpu_end_to_end + host_api_total)
  curobo: time.perf_counter() around solve_pose() + torch.cuda.synchronize()
```
