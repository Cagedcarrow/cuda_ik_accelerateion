# 2. 相关工作

## 2.1 传统 CPU 逆运动学库

Orocos KDL 是机器人领域常用的几何与运动学计算库，提供 FK、IK 与 twist/frame 等基础工具。它的重要价值在于接口稳定、工程集成成熟，但在本文这种大量独立目标位姿的批量求解场景中，KDL 的典型用法仍以 CPU 串行或轻量并行为主。对于标准化 benchmark，KDL 更适合作为“同模型、同阈值、同输入路径”的保守 CPU 参考，而不是吞吐上限。

除了 KDL，数值 DLS 也是广泛使用的通用 baseline。它的优点是实现直接、可控、可解释；缺点是当 batch 很大时，CPU 上逐目标求解的总时间会迅速上升。

## 2.2 GPU 机器人求解与 cuRobo

近年来，GPU 机器人求解器的代表性工作之一是 cuRobo。其核心思想是利用 GPU 上的大量并行 seeds 和并行优化，在碰撞感知 IK、轨迹优化和几何规划等任务上获得较高吞吐。对于本文，cuRobo 的意义在于：

- 它是真实可运行的 GPU 参考；
- 它覆盖了 IK 路径，且在工业界与研究界都有较强影响力；
- 它使用与本文不同的求解组织方式，因此可以作为强对比对象。

不过，cuRobo 并不是为本文这类“单一标准机械臂 + 本地自定义统一数据资产”专门设计的。为了进行公平比较，本文必须强制它读取同一 URDF 与同一 `tool0` 定义，这也是本文 benchmark 工程的一部分工作。

## 2.3 JAX / Python 路径与 PyRoki

PyRoki 把机器人运动学优化问题组织为可组合的变量与代价项，并依赖 JAX/JIT 在 Python 层实现较强的表达力。它的优势是研究灵活、接口现代、便于快速实验；但在本文的标准化 benchmark 中，它目前仍有两点限制：

1. 当前路径虽然已经接入共享外部 seed 文件，但仍然采用逐 target 的独立 JAX solve；
2. 它的 warm-up/JIT 行为必须与主 benchmark 时间口径分开记录，而且在统一 benchmark 上收敛与吞吐都明显偏弱。

因此，PyRoki 在本文中被保留为参考 solver，而不是主公平对比 solver。

## 2.4 本文与现有工作的区别

本文与已有 IK / GPU 工作的主要区别不在“是否使用 DLS”，而在**工程标准化与证据链闭环**：

- 我们首先统一模型、TCP、target/seeds、误差阈值与时间口径；
- 然后才讨论 CUDA 的 kernel 设计与性能优化；
- 最后再把实验、profiling 和论文表述互相校验。

这意味着本文的重点不是给出一个抽象的“更快 GPU IK”，而是给出一个**可以被重复运行、可以被审查公平性、可以明确指出未完成项**的标准化研究过程。
