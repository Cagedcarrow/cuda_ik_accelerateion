# 6. 扩展性验证：从 6DOF 到 7DOF

## 6.1 验证目标

为验证本文的 CUDA 批量 IK 框架能否从 6DOF（UR10）**数学一致地**扩展到冗余机械臂，本文选择了 Franka Panda（7DOF）作为扩展目标。这一验证的定位是：

- 证明框架的普适性——**不是**为 Panda 提供完整 benchmark 或生产级求解器；
- 展示从 6DOF 迁移到 7DOF 所需的**最小改动集合**；
- 验证迁移后 CUDA 实现的正确性（与 CPU 参考比较）；
- **不**产生与 cuRobo 或其他求解器的公平 benchmark 数据。

## 6.2 6DOF 到 7DOF 的迁移路径

### 必须改动的维度

相对于 UR10（6DOF），Panda（7DOF）的核心差异在于：

| 项目 | UR10 (6DOF) | Panda (7DOF) | 迁移方式 |
|------|------------|--------------|----------|
| Active joints | 6 | 7 | 参数化为 `DOF` 宏 |
| Jacobian | 6×6（方阵） | 6×7（非方阵） | 列数从 6 增至 7，仍为 6 行 |
| Hessian | 6×6 SPD | 7×7 SPD | 维度从 6 增至 7 |
| LDLT 求解器 | `ldlt_solve_6x6` | `ldlt_solve_7x7` | 新增 7×7 LDLT 分解 |
| FK segments | 6 段 | 7 段 | 循环次数从 6 增至 7 |
| 常量内存 origins | 96 doubles | 112 doubles | 按 URDF 数据自动生成 |
| 常量内存 axes | 18 doubles | 21 doubles | 按 URDF 数据自动生成 |
| 权重 schedule | 6 元素/level | 7 元素/level | 维度对应关节数 |
| **冗余自由度** | 无（6-6=0） | 有（7-6=1） | 零空间存在，seed 影响解的选择 |

### 保持不变的部分

以下组件从 6DOF 实现直接复用，**无需改动**：

- Rodrigues 旋转公式
- 4×4 矩阵乘法 (`mat44_mul`)
- 6DOF 姿态误差计算 (`pose_error`)
- `PaddedMat6x8`（Jacobian 矩阵仍为 6 行）
- 自适应阻尼调度策略
- 1 block/target, 128 threads/block 的线程映射

### 迁移工作量

从 6DOF 到 7DOF 的迁移涉及 **约 15 处改动**，全部为维度参数的机械调整：

- 7 处数组维度调整（`s_q`、`s_H`、`s_g`、`s_dq` 等）
- 3 处循环上界调整（FK segments、Jacobian 列、Hessian 构造）
- 1 处新增函数（`ldlt_solve_7x7`，从 6×6 版本扩展）
- 4 处模型常量调整（origins、axes、joint limits、weights）

其中 `ldlt_solve_7x7` 是唯一需要算法理解的改动——它保持了 6×6 版本的寄存器级实现风格，仅将矩阵维度提升至 7×7。

## 6.3 验证实验结果

### 实验设置

- 求解器：Damped Least Squares（数值 Jacobian + 自适应阻尼 + LDLT 7×7）
- 收敛阈值：pos_tol=0.03m, rot_tol=π/6, max_iter=160
- 测试规模：N=10 随机目标（由 URDF 模型生成）
- 参考实现：Python CPU DLS IK（与 CUDA 使用相同的算法逻辑）

### 验证结果

| 验证项 | 预期 | 实际 | 状态 |
|:-------|:-----|:----|:----:|
| Python FK 自洽性 | 通过 | 通过 | ✅ |
| Python FK vs yourdfpy 交叉验证 | 通过 | 通过 | ✅ |
| FK at q=0 恒等验证 | 通过 | 通过 | ✅ |
| CUDA FK vs CPU FK 最大误差 | < 1e-6 | **2.78e-16** | ✅ |
| CUDA DLS IK 收敛率（N=10） | ≥ 50% | **50%**（5/10） | ✅ |
| CUDA kernel 编译 | 通过 | 通过 | ✅ |
| CUDA kernel 运行稳定性 | 不崩溃 | 不崩溃 | ✅ |

### 关键结果

1. **CUDA FK 达到机器精度**：与 CPU FK 的最大误差为 2.78e-16，证明正向运动学计算在迁移后完全正确。

2. **IK 收敛率与 CPU 参考一致**：CUDA DLS IK 在 N=10 上的收敛率为 50%（5/10），与 Python CPU DLS IK 完全一致。这验证了 LDLT 7×7 求解器、数值 Jacobian 和自适应阻尼在 7DOF 场景下的联合正确性。

3. **50% 收敛率的合理性**：7DOF 冗余机械臂的 IK 求解比 6DOF 更具挑战性——零空间的存在使得解空间更加复杂，且随机 seed 可能落入收敛困难的区域。50% 的收敛率并非框架缺陷，而是 DLS 求解器在 7DOF 上的典型表现（CPU 参考取得相同结果）。

## 6.4 讨论

### 迁移成本

从 6DOF 到 7DOF 的迁移总工作量估计约为 **2–3 人日**，其中约 80% 是机械性的维度调整，仅 LDLT 7×7 求解器的扩展需要算法理解。这一低迁移成本表明本文的 CUDA 框架具有良好的**参数化可扩展性**——核心的线程映射策略、共享内存布局和迭代调度逻辑不受 DOF 数量影响。

### 与 6DOF 的性能差异预期

基于迁移逻辑分析，7DOF 相对于 6DOF 的预期性能变化为：

- **计算量增加**：FK 从 6 段增至 7 段（+17%），Jacobian 从 6 列增至 7 列（+17%），Hessian 从 6×6 增至 7×7（+36%），LDLT 从 6×6 增至 7×7（+78%）
- **寄存器压力增加**：更大的求解矩阵需要更多寄存器，可能降低 occupancy
- **收敛特性变化**：冗余自由度使得单 seed 收敛率下降，但多 seed 策略可弥补

定量 benchmark 仍需在实际硬件上完成，但基于以上分析，7DOF 的吞吐预计为 6DOF 的 **40–60%**（主要受 LDLT 7×7 的 O(n³) 计算增长限制）。

### 本研究中的定位

本节的目的是展示框架的**普适性**，而非提供 Panda 的生产级求解器。7DOF 的完整 benchmark（与 cuRobo 等求解器的统一口径对比）属于后续工作范畴。在本文中，6DOF（UR10）始终是主实验对象，7DOF 验证仅用于证明迁移路径的可行性与正确性。
