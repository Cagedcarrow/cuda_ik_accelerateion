# 5. 实验

## 5.1 实验设置

### 机器人模型与数据

- 主模型：官方 UR10（Universal_Robots_ROS2_Description v4.3.1）
- 主 TCP：`tool0`
- 数据生成：`seed=42`
- 主 seed 策略：`zero_seed`

### 收敛阈值

- 位置误差：`< 0.03 m`
- 姿态误差：`< 0.5236 rad`

### 时间口径

对 CUDA 主线，记录三类时间：

- `kernel_time_only`
- `gpu_end_to_end_time`
- `host_api_total_time`

对 cuRobo / PyRoki：

- 当前可稳定记录的是 `host_api_total_time`
- 预热 / JIT 已从主计时中排除并在备注中说明

### 主对比与参考对比

主对比 solver：

- `cuda`（B5 配置：mixed precision + adaptive damping + PaddedMat6x8 + constmem）
- `curobo`（NVIDIA GPU IK 求解器，L-BFGS + particle 搜索）

参考 solver：

- `numeric_dls`（CPU 数值 DLS 基线）
- `pyroki`（JAX/LM 实现）
- `kdl`（PyKDL 几何法基线）

### 结果分析

1. **CUDA DLS 在小中批量上显著占优**：在 N=100 时吞吐为 cuRobo 的 18.3–37.6 倍（B3 FP64 为 18.3 倍，B5 混合精度为 37.6 倍），在 N=500 和 N=1000 时分别领先 4.1–10.3 倍和 4.8 倍。这是因为每个目标仅需一个 block 的轻量级映射，而 cuRobo 的 particle 搜索（每目标 200 粒子 × 4 seeds）的开销在小批量下无法被充分摊销。

2. **混合精度（B5）缩小并反转了 N=5000 差距**：B3（FP64）在 N=5000 上落后 cuRobo 2.0 倍，而 B5（mixed precision）以 **180,962 targets/s 达到 cuRobo 吞吐的 1.25 倍**。这一提升主要来自两个因素的叠加：FP32 的 FK/Jacobian/Hessian 计算减少了 FP64 运算量并缓解了共享内存访问压力，同时 FP64 的 LDLT 路径保持了求解精度。NCU profiling 数据确认了加速的具体来源：B5 的 kernel 执行时间从 B4 的 2,920 μs 降至 827 μs（缩短 72%），bank conflict 从 3,522 降至 1,295（减少 49%），而 FP64 pipeline 仍保持 60.7% 利用率。

3. **两类路线的性能边界**：核心发现是，在本文测试条件下，轻量级 CUDA 映射路线在中小批量上 per-target 开销更低；cuRobo 的 particle 搜索优势仅在 FP64-only 条件下短暂体现（B3 vs cuRobo，N=5000），一旦本文方法也利用 FP32 计算能力（并在关键路径保留 FP64），即可在 N=100-5000 的测试范围内取得更高吞吐。

## 5.3 消融实验（B0–B6）

### 结构性设计项与可量化消融项

本文的 CUDA 实现包含两类设计选择：**结构性设计项**是框架的核心架构特征，在 baseline 中已固定启用，不参与独立消融开关；**可量化消融项**可在编译时独立切换，其性能影响可直接测量。

**结构性设计项**（所有消融级别默认启用）：
- 1 block/target、128 threads/block、四 warp 分工
- 寄存器内 6×6 LDLT 小矩阵求解
- 单 kernel 内完成全部 DLS 迭代

**可量化消融项**（编译时独立开关）：

| 级别 | ConstMem | PaddedMat | Adaptive Damping | Step Clamp | Branch Align | Precision |
|:----:|:--------:|:---------:|:----------------:|:----------:|:------------:|:---------:|
| B0 | — | — | — | — | — | FP64 |
| B1 | ✓ | — | — | — | — | FP64 |
| B2 | ✓ | ✓ | — | — | — | FP64 |
| B3 | ✓ | ✓ | ✓ | — | — | FP64 |
| B4 | ✓ | ✓ | ✓ | ✓ | ✓ | FP64 |
| **B5** | ✓ | ✓ | ✓ | — | — | **FP32+FP64** |
| B6 | ✓ | ✓ | ✓ | — | — | FP32+FP64+**Graph** |

B3 至 B4 增加步长钳位与分支对齐，B5 在 B3 的基础上切换为混合精度并关闭步长钳位与分支对齐，B6 在 B5 的基础上启用 CUDA Graph replay。B0-B2 追踪内存层次优化的逐步贡献，B3-B5 追踪数值策略与混合精度的叠加效应。

### 消融结论

1. **内存层次优化（B0→B2）**：常量内存和 PaddedMat6x8 作为可量化消融项，在小批量上提供约 5% 提升，在大批量上可忽略。说明工作集（96 doubles origins + 18 axes）轻松适配 L1 缓存。

2. **自适应阻尼（B2→B3）**：对收敛率影响最显著的数值策略——在小批量上因分支开销导致吞吐下降 62.4%，但在大批量上因解决固定 λ 的收敛失败而实现 **132–184% 的吞吐提升**。没有自适应阻尼时，B0-B2 在 N=5000 上收敛率仅 83.4%。

3. **混合精度（B4→B5）**：FP32 主体 + FP64 关键路径的方案在所有批量上带来 **148–154% 的吞吐提升**，同时收敛率保持 99.98% 以上。NCU 数据确认了加速来源：B5 kernel 时长从 B4 的 2,920 μs 降至 827 μs（缩短 72%），bank conflict 从 3,522 降至 1,295（减少 49%），FP64 pipeline 保持 60.7% 利用率。从当前 NCU 指标看，混合精度引入的类型转换没有表现为主导瓶颈；主要瓶颈仍为计算吞吐与寄存器压力。

4. **CUDA Graph（B5→B6）**：在 N=100 上 CUDA Graph replay 对 kernel 执行时间的影响在测量噪声范围内（~0% 差异），表明 kernel launch overhead 在当前配置下不是主要瓶颈。

5. **步长钳位 + 分支对齐（B3→B4）**：这两个优化在所有批量上持续降低吞吐 15–20%，建议面向吞吐的推理关闭这两项。

主求解器配置采用 B5（混合精度 + 自适应阻尼，关闭步长钳位与分支对齐），收敛率不低于 99.8%。B6（+CUDA Graph）在 N=100 上吞吐略高于 B5（111,238 vs 107,250 targets/s），差异约 3.7%，主要反映 launch/replay 机制变化而非核心 kernel 设计差异。

## 5.5 Nsight Compute 架构级分析

当前 NCU profiling 以 N=100 为代表样例，主要用于分析 kernel 内部的瓶颈结构（计算边界、寄存器压力、bank conflict）。N=5000 下的 SM 填充、wave 数和调度行为与 N=100 存在差异（主要体现为 grid 饱和度），但 kernel 内部的指令 mix 和内存访问模式基本保持一致，因此 N=100 的 profiling 结论对理解整体瓶颈具有代表性。以下分析均基于此认识。

### B4（FP64 全精度）N=100

| 指标 | 值 | 解读 |
|:----|---:|:-----|
| Compute throughput | 66.89% | 计算为主瓶颈 |
| DRAM throughput | 1.56% | 非带宽受限 |
| Registers/thread | 94 | 限制 occupancy 的主因 |
| Achieved occupancy | 32.51% | 受寄存器上限 × waves/SM 不足 |
| L1/TEX hit rate | 99.13% | 数据复用良好 |
| Shared bank conflicts | 3,522 | 存在共享访问冲突 |
| Local spilling | 0 | 无寄存器溢出 |

### B5（混合精度）N=100

| 指标 | 值 | 解读 |
|:----|---:|:-----|
| Compute throughput | 60.73% | 仍以计算为主 |
| DRAM throughput | 1.16% | 非带宽受限 |
| Registers/thread | 98 | 略高于 B4（FP32→FP64 转换逻辑） |
| Achieved occupancy | 33.3% | 与 B4 相近 |
| L1/TEX hit rate | 98.62% | 仍保持高命中率 |
| **Shared bank conflicts** | **1,295** | **较 B4 减少 49%** |
| Kernel duration | **827 μs** | **较 B4 2,920 μs 缩短 72%** |

### 关键发现

1. **kernel 不是 DRAM-bound**：两版本 DRAM throughput 均低于 2%。

2. **混合精度减少 bank conflict 49%**：FP32 数据宽度仅为 FP64 的一半，存储操作的自然对齐减少了冲突。

3. **FP64 pipeline 仍为最高利用率的计算单元（60.7%）**：尽管 FK/Jacobian/Hessian 已改为 FP32，LDLT 求解器仍使用 FP64，该路径维持了 SM 的计算压力。

4. **Occupancy 由寄存器压力主导**：94–98 个寄存器/线程限制了理论 occupancy 至约 33%，waves/SM 在 N=100 时仅 0.83 倍进一步降低了达到的 occupancy。

5. **Bank conflict 非瓶颈**：B5 的 1,295 次冲突仅占总共享访问波前的约 1%，即使完全消除，预计加速也低于 1%。

## 5.6 与 cuRobo 的技术路线对比

本文与 cuRobo 的比较是统一模型、统一 target、统一 TCP、统一阈值和统一时间口径下的任务级比较，而非等计算量、等精度、等 seed 数或等优化器结构的比较。cuRobo 采用 FP32、多 seed/多 particle 的优化搜索路线；本文采用混合精度、单 seed、DLS 迭代与 1 block/target 的轻量级 CUDA 映射。因此，本文结论应解释为在不同 batch size 下两类 GPU IK 路线的吞吐边界与适用区间，而非某一求解器在一般意义上全面优于另一求解器。

两条路线的具体差异如下：

| 维度 | 本文 (CUDA DLS) | cuRobo |
|:----|:----------------|:-------|
| 求解器 | Damped Least Squares (DLS) | L-BFGS + particle 搜索 |
| 精度 | **混合精度** (FP32 主体 + FP64 LDLT) | FP32 |
| 每目标映射 | 1 block × 128 threads | 多 particle × 多 seed |
| 并行策略 | 轻量级单 kernel | 批量 particle 搜索 |
| 批处理范围 | 1–5000+ | 100–5000+ |

cuRobo 的核心创新在算法层（L-BFGS 与 particle 搜索的结合），而本文的核心创新在 GPU 硬件适配层（线程映射、混合精度调度、共享内存布局、寄存器级求解器、常量内存广播）。在本文测试范围内，两条路线不再存在明确的交叉点：混合精度的引入使 B5 配置在 N=100-5000 的测试批量上均达到或超过 cuRobo 的 IK 吞吐水平。
