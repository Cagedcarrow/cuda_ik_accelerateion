# 1. 引言

## 1.1 研究背景

机械臂逆运动学（inverse kinematics, IK）是机器人控制、抓取、标定和轨迹跟踪中的基础问题。对于单次 IK 查询，传统 CPU 数值求解器已经能够在毫秒到几十毫秒范围内给出可用结果；但当任务转为**同一模型、同一阈值下的批量可达目标位姿求解**时，求解器的并行结构、初始化策略和评测口径会显著影响结果。特别是在消费级 GPU 上，小矩阵、多迭代、强控制流依赖的 IK kernel 并不天然适合高吞吐执行，是否值得用 CUDA 重写，需要建立在统一模型、统一数据和统一阈值的公平比较之上。

## 1.2 本文关注的问题

本文关注的是**标准机械臂随机可达目标位姿集上的批量 IK 求解**，而不是路径规划，也不是完整运动规划流水线。我们不讨论障碍物搜索图、全局采样规划、轨迹优化或时间参数化，而是将问题严格限定为：

- 使用官方 UR10 模型；
- 在相同 `tool0` 末端定义下生成一组可达目标位姿；
- 给定同一组初始 seed；
- 在相同位置/姿态误差阈值下比较不同求解器的批量求解效率与收敛率。

这个问题定义有两个现实动机。第一，工程上常见的抓取、标定和大规模离线采样任务，本质上需要的是大量 IK 查询而不是规划器全流水线。第二，很多“GPU IK 比 CPU 快”的结论实际上混入了不同 URDF、不同 TCP、不同初始化和不同时间口径，缺乏可复现性。

## 1.3 研究难点

将一个旧有的 CUDA IK 工程迁移到标准模型，并不只是换一份 URDF。本文在重构过程中遇到了三个关键难点：

1. **模型一致性难点**。旧工程使用的是自定义装配体 TCP 和固定数据集，而标准化后必须改为官方 UR10 与 `tool0`。这会改变 FK 常量、目标位姿分布和 seed 可解性。
2. **数值一致性难点**。同一个 DLS 框架下，姿态残差、数值 Jacobian 和最终误差统计如果不一致，会导致位置误差很小但姿态误差长期停留在错误分支。
3. **性能一致性难点**。批量 GPU 求解器的吞吐不仅取决于 kernel 本身，还取决于 launch 策略、常量内存、共享内存布局和 host 侧时间口径定义。

## 1.4 本文贡献

本文的贡献不在于提出全新的 IK 数学算法，而在于把“标准化研究工程 + CUDA 低层优化 + 公平 benchmark + 文档一致性”完整串起来：

1. 建立了一个独立于旧工程的新子项目 `standard_robot_cuda_ik/`，统一了目录结构、数据资产和 benchmark 入口。
2. 使用 Universal Robots 官方 ROS2 描述仓库生成平铺 UR10 URDF，并用 `yourdfpy` 对 CPU FK 做了机器精度级验证。
3. 构建了 `seed=42` 可复现的 target/seeds 生成链路，并额外给出 hash 一致性验证报告。
4. 在标准化迁移中定位并修复了影响 CUDA 收敛的三个核心一致性问题：固定变换折叠、输出 FK 对齐、姿态残差定义。
5. 在 N=100/500/1000/5000 四个主规模上完成与 cuRobo 的统一口径比较：CUDA 在小中批量（N<=1000）上领先 4.8-37.6 倍（混合精度版本），混合精度版本在 N=5000 上达到 cuRobo 1.25 倍吞吐。
6. 通过 Nsight Compute 动态 profiling 给出硬件层面的定量证据：kernel 为计算边界（60.7% SM throughput），bank conflict 非瓶颈（约 1% 波前），寄存器压力是 occupancy 主限因素。

## 1.5 论文范围与边界

本文只写**真实完成**的实验，不写假结果：

- 7DOF Panda 目前只有扩展计划，没有正式 benchmark 结果；
- KDL 已补齐真实 PyKDL 基线，但仍只是 CPU 参考路径；
- PyRoki 已接入共享外部 seed，但吞吐与收敛仍不足以进入主对比 solver；
- 完整 B0-B6 独立消融已全部跑完，其数据构成第 5 节的核心内容。

在这一边界下，本文的目标是提供一份**完整、诚实、可继续迭代**的 Markdown 论文初稿。
